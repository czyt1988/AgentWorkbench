## 界面形态（第 3 版：统一 Markdown 工作台窗口）

**提示词撰写与 Markdown 预览合体**：从现有预览窗演化出「Markdown 工作台」独立窗口，
同一个窗口、同一套编辑器与渲染管线，两种模式：

- **提示词模式**（完整形态）：顶部 SARibbon `RibbonBar`（**单行模式**）+ 左右属性区 +
  中间「文档 tab 条 + Preview/Split/Source 三态 + 状态条」。
  **所有动作进 Ribbon 标签页，侧栏只放「拿什么素材」「看什么状态」**——这条边界沿用第 2 版。
- **文档模式**（双击 .md 进来的形态）：同一窗口收起侧栏、Ribbon 折叠（`minimumMode`），
  只保留「开始 / 视图」两类标签页——它就是原来的 Markdown 预览，但住在同一个壳里，
  保留大纲、搜索、三态、保存导出，并留一个单向升级口「从这份文档新建草稿」（P1）。

> SARibbon 以 submodule 引入（`third_party/SARibbon`，地址 https://gitee.com/czyt1988/SARibbon ），
> 构建期 `add_subdirectory`；离线初始化沿用 spdlog 的本地克隆惯例，详见 `提示词撰写-11` §五。

## 一句话目标

把「提示词撰写」从**一张草稿纸**（一个全局 `draft` + 一个文件树）升级为**一座 Markdown 工作台**：
能攒（模板与收藏）、能改（编辑体验与体检）、能装配（上下文引用）、能管（多草稿、历史、恢复）、
能看（统一窗口的预览、查阅、文件关联）。「发送到 agent」已移出规划——本窗口**永远不发送**，
交付只有复制。

## 五大功能组

| 组 | 主题 | 解决的问题 | 优先级分布 |
|---|---|---|---|
| **A** | 模板与库 | 常见结构每次从零手写；写了 10 条只活最后一条 | P0 为主 |
| **B** | 编辑体验 | 格式工具只有 3 个按钮；无查找替换；无法自查提示词质量 | P0 为主 |
| **C** | 上下文装配 | 只能引用路径，不能带行号/多选/内联；不知道写多长 | P0 为主 |
| **D** | 工作流与草稿生命周期 | 单一草稿互相覆盖；崩溃丢字；关窗丢会话 | P0/P1 混合 |
| **E** | 统一窗口与查阅 | 预览与撰写是两套割裂的编辑器；.md 没有轻量打开途径；长文档查阅手段薄 | 骨架 P0/P1，查阅项 P1/P2 |

功能全表（编号 / 名称 / 优先级）见 `提示词撰写-01-现状与欠缺.md` 的「欠缺 → 对应功能」一节，
或各分组文件开头的表格。

## 贯穿全程的五条底线

1. **不写迁移代码**：`tools.json` 新增键靠「缺键取默认值」的读侧容错完成，`draft` 之类的旧键
   **只加不改不删**（键名是磁盘格式的一部分，改名等于丢用户数据）。
2. **永远不发送**：「发送到 agent」已整体移出规划。本窗口不存在任何发送路径：回车只换行，
   交付只有复制。这条产品主张比第 2 版的「默认关闭」更强——新增任何功能都不得引入发送路径。
3. **离线纯规则优先**：体检、token 估算、变量解析都先做不依赖模型的版本，模型辅助单列为 P2 实验项。
4. **动作只有一处出口**：每个动作要么在 Ribbon 里，要么在侧栏里，**不许两处都有**。
   Ribbon 是动作的唯一权威入口，侧栏是素材与状态的浏览器；页内右键菜单仅保留「光标处上下文」
   才合理的那几条（撤销/剪切/格式），且与 Ribbon 共用同一批 `MarkdownEdit` 动作。
5. **第三方模块不穿透到领域层**：SARibbon 只出现在 `app/`（链接 + 注册）与 QML（`import SARibbon`）里；
   `awb_tools` 的 C++ 照旧只依赖 `awb_core` + `awb_theme`（见 `提示词撰写-11` §四.4）。
   统一窗口 QML 归 **workbench（L3）**——它天然横跨 tools 与 markdown 两个域；
   其余跨域动作照旧经 `workbench` 意图入口（见 `提示词撰写-08` §四、`提示词撰写-12` §八）。
