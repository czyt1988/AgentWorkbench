# 提示词撰写板块 · 现状与欠缺（第 3 版）

> 索引见 `提示词撰写-00-总览与索引.md`。本文的现状判断全部来自对代码的阅读，
> 文件与类名可直接核对。
> 第 3 版把 **Markdown 预览窗**也纳入盘点范围（窗口整合的起点事实）。

## 一、现状盘点

### 1.1 提示词页（`src/tools/`）

`src/tools/qml/ToolsPage.qml` 是主窗里的一个 `ColumnLayout` 页面：`PageHeader`
（标题 **Prompt Writing**，动作槽里放 **Copy**）下面是一个 `SplitView`，左面板是工作区
文件树，右面板是提示词编辑区。右键菜单 `src/tools/qml/MarkdownContextMenu.qml` 提供一个
34 px 的格式工具栏（加粗 / 代码 / 要点列表）加撤销、重做、剪切、复制、粘贴。
页面**切页即销毁**（无 `keepAlive`）：切到别的页面再回来，撤销栈、滚动位置、选区全丢
（草稿正文有防抖落盘，不丢）。

### 1.2 Markdown 预览窗（`src/markdown/`）

`src/markdown/qml/MarkdownPreviewWindow.qml` 是独立 `ApplicationWindow`，由
`MainWindow.qml` 的 `Loader` 按需创建、**关掉即销毁**（WebEngineView 的渲染进程与
约 4 MB 运行时不宜常驻）。已有能力：Preview/Split/Source 三态、大纲（块级锚点击滚动）、
页内搜索（自研，绕开 `content-visibility` 对原生查找的破坏）、字号/宽度视图设置、
导出 HTML、外部浏览器打开、**字节保真的保存**（BOM/换行/UTF-8 形状记录在
`MarkdownDocument`）、外部修改监听（watcher + 窗口激活时兜底重比）。
**单文档**：开第二个文件是复用窗口换内容。源码编辑区是裸 `ATextArea`
（无高亮、无格式动作）。能力只存在于 Qt 6 + WebEngine 构建
（`markdown.available` 恒真/恒假）。跨域入口：`WorkbenchContext::previewMarkdown()` /
`canPreviewMarkdown()`（`src/tools` 不得 include `src/markdown`）。

### 1.4 当前设计的两条明确主张（改动时不能无意中破坏）

1. **绝不误发**：回车只换行，页面没有发送按钮。第 3 版把它**升级为窗口级主张**：
   统一窗口不存在任何发送路径（D5 已整体移出规划，见 `提示词撰写-09` D-1）。
2. **只读工作区、只写自己的文件**：页面的读取只有工作区文件树，写入只有 `tools.json` 和系统剪贴板；
   文件 tab 的保存是用户显式动作（预览窗既有语义，带入统一窗口）。
   任何新功能如果会松动这两条，必须在文档与界面文案里显式改写主张，而不是悄悄加一个按钮。

### 1.5 两个编辑器的割裂（窗口整合的直接动因）

同一个仓库里存在两套 Markdown 编辑体验：提示词页的编辑器有高亮、格式动作、但无预览、
切页丢状态；预览窗的源码区无高亮、无格式动作、但有高质量渲染与字节保真保存。
用户看到的则是「两个不相干的窗口」。统一窗口把两者合并为一个编辑器本体
（`ATextArea` + `MarkdownHighlighter` + `MarkdownEdit`）+ 一个渲染管线（`MarkdownChunker`
分块 + 增量 + `content-visibility`）——管线吃文本不吃文件，草稿天然可复用
（`提示词撰写-12` §2.4）。

## 二、欠缺清单（按痛感排序，第 3 版扩充）

| # | 欠缺 | 具体表现 | 后果 |
|---|---|---|---|
| 1 | **没有沉淀** | 草稿只有一个，没有收藏、没有历史、没有库 | 写了 10 条提示词，只有最后一条活着；好的表述无法复用 |
| 2 | **没有模板** | 修 bug / 加功能 / 写测试 / 代码审查每次都从零手写同一种结构 | 起步成本高，且结构质量随心情波动 |
| 3 | **没有体检** | 无法判断提示词是否够 agent 用（技术栈？文件？验收标准？路径方向？） | 写出含糊提示词、拿到含糊结果，再回头猜原因 |
| 4 | **没有多任务** | 单一全局草稿 | 同时开两个任务，草稿互相覆盖 |
| 5 | **格式工具太薄** | 只有加粗/代码/要点，缺标题、编号列表、引用、链接、围栏语言标注、表格、分隔线 | 长提示词结构靠手打，容易漏写围栏语言 |
| 6 | **文件引用太浅** | 只能整文件引用路径；无行号、无多选、无内联内容、无目录骨架 | 想指「这个文件第 120–140 行」只能手打；agent 读不到文件时无解 |
| 7 | **不知道自己写了多长** | 无字符数/token 估算/上下文占用提示 | 容易写出超上下文的长提示词，或过度内联 |
| 8 | **.md 没有轻量打开途径** | 双击 .md 只能开 VS Code 这类重编辑器；本应用有渲染管线却接不到系统文件关联 | 「看一下渲染好的 Markdown」这件事的本应用路径不存在（E2） |
| 9 | **跨会话不可靠** | 500 ms 防抖窗口内崩溃/强杀丢最后一次编辑；预览窗关掉即销毁无会话恢复 | 长提示词白写；重开窗口从零开始 |
| 10 | **草稿与工作区脱钩** | 换工作区不清空不新建 | 草稿内容与文件树指向的项目可能不是一回事，容易插错引用 |
| 11 | **预览与撰写割裂** | 两套编辑器、两套窗口；提示词无预览、预览窗无格式动作 | 两个功能各缺对方的长处；用户要在两个不相干的窗口间切换 |
| 12 | **长文档查阅手段薄** | 大纲/搜索有，但无书签、无本地高亮、无文档版统计；且这些都只在预览窗 | 和 Markdown 文件长时间交互的 agent 工作流里，回看成本高（E5–E7） |

原第 1 版欠缺 8「交付差半步」已随「发送」一起删除（决策 D-1）：复制是本窗口唯一的交付，
「差的那半步」用「窗口跨页常驻 + agent 标签页在外壳里」来缓解——写完复制、切 tab、粘贴，
窗口状态不丢。

## 四、为什么现在做

- 提示词页的两个原始痛点（手拼相对路径、误触回车）都已解决，继续留在一个全局 `draft`
  上，收益已经见顶。
- **预览域的资产正好是整合的地基**：渲染管线（分块/增量/可见性）吃文本不吃文件、
  `MarkdownDocument` 的字节保真保存、大纲与块级锚、搜索——统一窗口让这些资产同时服务
  草稿与文件，边际成本远低于重做。
- 仓库其它既有资产覆盖规划的大部分：`A*` 组件架、`core::JsonStore` 的原子写、
  `default_*.json` 的「数据不是代码」惯例、`LegacyImport` 的首启动复制、
  `MarkdownEdit` 的纯静态光标操作（可单测）、SingleApplication 的消息通道（文件关联
  第二实例路径现成）。新增功能基本不需要新造基础设施。
- 规划里的 P0 全部可以离线、可单测（`tst_tools`、`tst_markdown` 已有纯层用例传统），
  体检/预算/变量不触碰 WebEngine，因此两个 Qt 版本（Qt 6 主线 + Qt 5.15.16 兜底）
  都能按同一份设计落地（窗口的降级形态见 `提示词撰写-12` §九）。
