# A 组 · 模板与库

> 索引见 `提示词撰写-00-总览与索引.md`；现状见 `提示词撰写-01`；字段级设计见 `提示词撰写-06`；
> 存储与兼容见 `提示词撰写-07`；**落点是统一工作台窗口 Ribbon 的「提示词」标签页 + 左侧属性区**
> （窗口双模式与 tab 模型见 `提示词撰写-12`，面板地图见 `提示词撰写-08`）。
>
> 这一组直接解决 `提示词撰写-01` 欠缺清单的 **1（没有沉淀）** 与 **2（没有模板）**，
> 也是用户最早提出的设想：**提供固定模板，让用户最简单快捷地得到想要的效果**。
> 模板动作只对**草稿 tab** 生效（文件 tab 是别人的文档，不往里插模板）。

## 二、A1 模板库与固定模板

### 2.1 交互（Ribbon 版）

模板的触达面拆成两处，各司其职：

**(a) Ribbon「提示词」标签页 —— 快速套用。**
- **模板 Panel** 放一个 `RibbonGallery`：`RibbonGalleryGroup` = 分类（修 Bug / 加功能 / 测试 / 审查 /
  重构 / 文档 / 解释 / 提交…），`RibbonGalleryItem` = 模板条目，`captionStyle` 用
  `Ribbon.GalleryIconWithText`。单击 item 即触发 `onTriggered` → 插入模板（不是替换）。
- **约束（必须知道）**：`RibbonGallery.groups` 是 `QQmlListProperty`，**只能静态声明、不能绑模型**。
  所以 gallery 里放的是**内置固定模板**这一不变集合——正好符合「固定模板一键套用」的诉求；
  用户自建模板不放 gallery。
- 同一 Panel 里再放 `Insert Template…`（`InstantPopup`，列出全部模板含用户自建）、
  `Save as Template`、`Manage Templates`。

**(b) 左侧属性区「模板库」段 —— 浏览与管理。**
- 一条 `ASearchField` + 一枚分类/标签过滤 + 一个可滚动的模板列表
  （沿用 `AListRow` / `ASectionHeader` / `APill` 的既有形态），承载**全部**模板：
  内置 + 用户 + 用户改写内置（三层的合并顺序见 §2.3）。
- 这一段也是「点一下插入」的入口，但它存在的理由是：模板数量长起来之后 gallery 放不下，
  而检索、标签过滤、编辑/删除/另存都需要一个常驻列表。
- 「收藏夹」（A4）是紧接着的另一段，形态相同、数据不同。

> 为什么不在左侧区做 Tab、也不把两者合成一段：模板（骨架，要填变量）与收藏（成稿，可直接用）
> 在使用上是两种动作，混在一段里用户每次都要先分辨；而左侧区此时已经有文件树这一段，
> 三段纵向堆叠比「Tab 里再套 Tab」更接近 `designs.md` 的侧栏/面板惯例。

### 2.2 起步内置模板清单（建议 8–10 条）

| 标题 | 适用场景 | 骨架要点 |
|---|---|---|
| Fix a bug | 报错/行为不对 | 现象、复现步骤、期望行为、相关文件引用、验收（跑什么测试） |
| Add a feature | 新能力 | 目标、约束、涉及模块、边界（不做什么）、验收标准 |
| Write tests | 补测试 | 目标模块、要覆盖的路径、测试框架、运行命令 |
| Review code | 审查改动 | 审查范围（文件/区间）、关注点（正确性/边界/性能/命名）、输出格式 |
| Refactor | 结构整理 | 现状问题、期望结构、不可改变的行为、验证方式 |
| Write documentation | 文档 | 面向读者、要覆盖的问题、语气、落地位置 |
| Explain this code | 理解代码 | 文件/区间引用、解释深度、是否要画出数据流 |
| Commit message | 提交信息 | 改动摘要、约定格式、语言 |
| Reproduce an issue | 复现问题 | 环境、输入、期望、实际、日志引用 |
| Plan a change | 先规划再动手 | 目标、约束、希望先给出方案再实现 |

每条模板只写**结构与提问**，不写死具体项目信息——填空由 A2 的变量承担。

### 2.3 层级与覆盖关系

三层，优先级从低到高：

1. **内置**：`config/default_prompt_templates.json`（随包、只读、与 `default_agents.json`、
   `default_file_icons.json` 同一套「内置定义来自数据文件」惯例。**不要在 C++ 里硬编码模板条目**）。
2. **用户**：数据根下的用户模板目录（可手改、可备份、可进 git）。用户改写过的内置模板**浮到前面**，
   与 `agents.json` 的「内置每次随包重生成 + 用户改动优先」是同一心智。
3. **工作区级**（P2 可选）：工作区目录内一份团队共享模板文件，方便同一个仓库多人共用同一套骨架。

## 三、A2 占位变量填充

### 3.1 语法

| 形式 | 含义 |
|---|---|
| `{{task}}` | 必填占位 |
| `{{task:重构文件树}}` | 带默认值 |
| `{{file:path}}` | 类型提示为路径，填的时候给文件/目录选择器 |
| `{{workspace}}` `{{date}}` `{{branch}}` `{{selection}}` | 内置变量，自动求值，不打扰用户 |

### 3.2 交互

- 插入模板后若含占位变量 → 弹一张小表单，**键盘流式**填写：Tab 跳下一个、回车确认、Esc 取消。
- 可以「跳过」：未填的占位符**原样留在正文里**并被高亮成待办色，避免用户忘了填直接复制走。
- 表单里每一项显示它在正文中的上下文片段，避免用户不记得这个变量用在哪。
- 同一变量名出现多次 → 一次填写，全部替换。
- 已经填过的变量（例如一条草稿里的 `{{workspace}}`）再次插入同一模板时可复用上次的取值（P2）。

### 3.3 边界

- 变量解析是**纯字符串操作**，不联网、不调模型；解析规则与用例见 `提示词撰写-06`。
- 不引入模板语言（循环、条件、表达式）。一旦需要，说明该做的是模板组合（A6）而不是编程语言。

## 四、A3 存为模板

- 入口：Ribbon「提示词」标签页的 **Save as Template**；标题行快速访问栏也放一个；
  快捷键 Ctrl+S 走同一条路（P1）。
- **只能从草稿存**：激活的是文件 tab 时按钮禁用（tooltip 说明「先从文档新建草稿」，
  即 E4 的单向升级口）。
- 自动做事：
  - 标题取草稿首行（去掉 markdown 记号），空则弹一个只填标题的小框（`Loader` 惰性创建）；
  - 分类默认「我的模板」，可改；
  - **自动识别可变成变量的片段**：`` `./src/x.cpp` `` 这类文件引用 → 提议转成 `{{file}}`；
    出现多次的项目专有名词 → 提议转成 `{{name}}`（提议式，用户可逐条接受/忽略）。
- 结果写入用户模板目录（一个模板一个文件，见 `提示词撰写-07`），并 toast 给出「打开模板目录」的直达动作。

### 4.1 模板的「编辑」怎么算够用（第一版）

仓库惯例是「用户数据放数据根下、用户可手改」（`agents.json`、`file_icons.json` 都是这个态度）。
因此第一版**不做内置编辑器**：`Manage Templates` = 打开模板目录 + 一个搜索列表 +
「复制一份来改」/「删除」。真要做就地编辑器，那是另一个功能（富文本 + 头部字段校验 +
目录写盘），排在 A7 之后。

## 五、A4 收藏夹

- **与模板的区别必须在使用上看得见**：模板是骨架（带占位符、要填），收藏是成稿（可直接用）。
  两者在界面上分处两段/两处，不要混在一个列表里。
- 入口：
  - Ribbon「提示词」标签页的 **收藏 Panel**：`Favorites`（`InstantPopup` 列出收藏）、
    **★ Save to Favorites**、`Copy Favorite`；
  - 左侧属性区「收藏夹」段：常驻列表，悬停给 **插入**、**复制**、**删除**。
- 收藏存正文 + 标题 + 可选标签 + 创建时间；上限与 MRU 语义沿用现有 `ToolsStore` 的既有风格
  （超出上限淘汰最久未使用，且淘汰时明确提示）。

## 六、A5 搜索与标签

- 检索范围：模板标题、描述、标签、正文（正文命中给一句摘要）。
- 标签来源：内置分类 + 用户自定义标签；标签过滤与检索是**与**关系。
- 检索性能：数量级是几十到几百条，纯内存过滤即可，不必上索引。

## 七、A6 模板包含与组合（P2）

- `{{> 常用约束}}` 在插入时被替换成另一份片段的内容（片段与模板同目录、同格式，只是不带 front matter 标题）。
- 组合视图：勾选多个片段按顺序拼成一条长提示词，用于「系统提示 + 任务 + 约束 + 输出格式」这类结构。
- 防环：包含深度上限（例如 5 层）+ 检出循环时报错而非死循环。这条**必须有测试**。

## 八、A7 导入 / 导出（P2）

- 导出：把用户模板目录与收藏打包成一份 JSON（可读、可 diff、可进 git）。
- 导入：合并式导入，同名冲突给「保留两者 / 覆盖 / 跳过」三选，绝不静默覆盖用户内容。
- 用途：同事之间交换常用提示词；将来若做社区模板库，这是天然入口。

## 九、A8 模型辅助生成（P2，需先决策）

- 设想：输入一句「给这个 Vue 项目补一套订单模块的单元测试」→ 生成带占位符的骨架。
- **前提问题**：本窗口当前不联网。要走这条路必须显式开一条实验开关，并在文档里写清「这一项会把你的
  描述发到某处」。在决策 D-14 拍板之前**不排期**。
- 若最终采纳：实现上应经由工作台已有的跨域入口，不在 `awb_tools` 里直接发网络请求
  （`awb_tools` 只依赖 `awb_core` + `awb_theme`，见 `提示词撰写-08`）。

## 十、验收要点（补入 `提示词撰写-06` 的用例清单）

- 旧用户升级后**草稿不丢**（`draft` 键读侧兼容）。
- 内置模板 + 用户模板 + 用户改写内置模板的合并顺序正确。
- 变量：同名多次全替换、带默认值、内置变量求值、跳过后占位符仍在且高亮。
- 存为模板：首行取标题、自动提议变量、写入目录后模板库立即可见。
- 包含：深度上限与循环检出（不会死循环）。
