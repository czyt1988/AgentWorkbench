# B 组 · 编辑体验

> 索引见 `提示词撰写-00-总览与索引.md`；现状见 `提示词撰写-01`；
> 规则清单与算法见 `提示词撰写-06`；**这些动作的落点是统一工作台窗口 Ribbon 的「开始」标签页**
> （窗口与 tab 模型见 `提示词撰写-12`，面板与按钮的完整地图见 `提示词撰写-08` §2.2）。
>
> 这一组解决欠缺 **5（格式工具太薄）**、**3（没有体检）**，以及编辑手感上的若干缺口。
> 全部是离线能力，可在 `tst_tools` 里用 `QTextDocument` 直接驱动测试。
> 统一编辑器红利：格式动作、查找替换、光标状态查询对**草稿 tab 与文件 tab 的源码区
> 同样生效**（`提示词撰写-12` §2.3）——实现一份，两边受益。

## 二、B1 格式工具栏补全

### 2.1 现有三项的定位

`MarkdownEdit` 的三个动作是**纯静态光标操作**（`applyBoldToCursor` 等），一次 `beginEditBlock` 一步撤销，
不依赖焦点即可读写选区——新加的动作必须沿用这套形状，这样才可单测、才能在菜单抢走焦点后照常工作。

### 2.2 建议新增

| 动作 | 行为要点 |
|---|---|
| 标题 | 行首切换 `#`/`##`/`###`（下拉或循环）；已有标题时改级而不是叠加 |
| 编号列表 | 选区每行加 `1. ` 递增；再点一次去编号 |
| 引用块 | 选区每行加 `> `；空行保持空行 |
| 行内链接 | 有选区：`[选区](url)`，光标停在 url；无选区：`[](url)` |
| 围栏代码块（带语言） | 现 `applyCode` 在选区含换行时生成围栏但不带语言；补一个**语言选择**（下拉，含常见语言 + 上次使用 + 留空） |
| 表格骨架 | 插入 表头 + 分隔行 + 一行示例，列数可选（3 列默认） |
| 分隔线 | 插入 `---`（前后空行规范化） |
| 任务清单 | `- [ ] `（agent 提示词里常用来写验收清单） |

### 2.3 界面形态（Ribbon 版）

动作**全部进 Ribbon 的「开始」标签页**，按语义分 Panel（每个 Panel 内是若干 `RibbonToolButton`）：
「开始」页对所有 tab（草稿与文件）可用，是文档模式下仅剩的两个标签页之一。

| Panel | 按钮 |
|---|---|
| 剪贴板 | **Copy**（主交付动作，快速访问栏同款）、Paste（`MenuButtonPopup`：纯文本 / 保留格式）、Cut、Copy All |
| 撤销 | Undo、Redo |
| 字形 | Bold、Italic、Strikethrough、Inline Code（均 `checkable`，反映光标处状态） |
| 段落 | Heading 1/2/3（`MenuButtonPopup`）、Bulleted List、Numbered List、Task List、Quote、Divider |
| 代码 | Fenced Code Block（`MenuButtonPopup` 选语言）、Insert Table（`InstantPopup` 选行列） |
| 查找 | Find & Replace、Goto Line |
| 格式 | Clear Formatting、Paste Cleaning（`checkable`） |
| 保存 | Save（仅文件 tab 有意义；草稿 tab 禁用，tooltip 说明「草稿自动保存」） |

三条随之而来的约束：

1. **单行模式下 `proportion` 失效**，按钮一律按小按钮（图标 20×20 + 右侧文字）渲染，
   所以主次只能靠 Panel 顺序与 `RibbonSeparator` 表达，且**按钮文字要短**。
2. **`checkable` 按钮必须有真实的查询侧**：现有 `MarkdownEdit` 只有三个动作、没有「当前光标处
   是否已加粗 / 是第几级标题」这类查询。要先补 `Q_INVOKABLE` 查询接口，再让按钮 `checked` 绑它；
   没有查询接口的动作**不要设 `checkable`**（否则是个会骗人的按钮）。
3. **窗口内右键菜单降级为「光标处上下文」菜单**：保留撤销/重做/剪切/复制/粘贴与高频三项即可，
   其余格式化动作搬到 Ribbon，避免同一动作两处各写一份（文案与启用态必然漂移）。
   菜单本体继续用本仓的 `AMenu`（Ribbon 的菜单体系只认 `RibbonMenuItem`，两者不能混用）。

编辑区上方**不再需要常驻格式条**——Ribbon 的「开始」页就是它。原来草案里的
「格式条 / 右键菜单二选一」问题由此消解；若用户折叠了 Ribbon，则用 `minimumMode`
一键展开即可，不需要另做一条工具条（`AWB_ENABLE_RIBBON=OFF` 的降级形态另有一条
普通工具栏，见 `提示词撰写-09` 小决策 12）。

## 三、B2 查找 / 替换

- 触发：Ctrl+F（P1 起给窗口级快捷键）、Ribbon「开始」页查找 Panel 的按钮、右键菜单一条。
- 形态：编辑区顶部滑出一条**页内查找条**（不弹对话框），字段为 查找 / 替换、按钮为 上一个 / 下一个 /
  替换 / 全部替换、开关为 区分大小写 / 全词。
- 命中高亮用主题的 highlight 语义令牌；当前命中格外强调。
- 行为约定：从光标处向后找、到尾部回卷并提示「已回卷」；替换单项后自动跳到下一个。
- 「全部替换」给一次确认并显示替换条数。
- 实现落点：`QTextDocument::find()` / `QTextCursor` 操作，放在 `MarkdownEdit`（或同级新类），
  与格式化动作一样是纯文档操作，可单测。

## 四、B3 清空草稿的确认与可撤销

- 现状：没有清空入口，但「替换全文」类操作（插入模板替换、恢复历史版本）会静默覆盖长内容。
- 入口（Ribbon）：**草稿**标签页的 Close/Delete、「开始」标签页的 Clear Formatting 属另一回事；
  清空正文放在**草稿**标签页（与「新建草稿」相邻，语义相近）。
- 规则：**任何会丢掉超过一定长度（建议 200 字符）内容的操作**，要么二次确认，要么执行后给
  toast + **撤销**动作（撤销 = 把旧内容写回，并保留在历史快照里，见 D2）。
- 清空草稿本身：确认弹窗 + 「已清空，撤销」toast 双保险。确认弹窗用 `Loader` 惰性创建
  （Ribbon 内不得急切实例化 `Popup`，见 `提示词撰写-11` §四.2）。

## 五、B4 快捷键提示面板

- 一个只读的浮层/对话框，列出：Ctrl+F 查找、Ctrl+N 新建草稿、Ctrl+S 存为模板、
  Esc 关查找条、以及既有的撤销/重做/剪切/复制/粘贴。
  （没有发送快捷键——发送功能不存在，见 `提示词撰写-09` D-1。）
- 入口：Ribbon **视图**标签页的 Help Panel 里一条 **Shortcuts…**（也可同时在右键菜单给一条）。
- 文案必须与实际绑定一致，且全部是英文源串 + `qsTr()`。
- 浮层同样走 `Loader` 惰性创建。

## 六、B5 变量占位按钮

- 选中文字 → 点按钮 → 变成 `{{变量名}}`，并**立即选中变量名**方便直接改名。
- 没有选区 → 插入 `{{}}` 且光标在中间。
- 与 A2 的变量语法共用同一份解析/校验（不重复实现两套语法）。

## 七、B6 打字机模式

- 开关落点：Ribbon **视图**标签页 → 编辑 Panel → **Typewriter Mode**（`checkable`）。
- 开启后光标行保持视口中上三分之一位置，正文整体滚动；关闭时恢复普通滚动。
- 价值场景是**长提示词**：写到最后几屏时不用追滚动条。
- 实现注意：编辑区是 `Flickable` + `TextArea.flickable` 的组合（滚动由 `Flickable` 承担），
  打字机模式需要在光标位置变化时调 `contentY`，属于对现有滚动结构的增强，不改结构本身。
- 默认关闭，记住开关状态（写进 `tools.json`）。

## 八、B7 粘贴清洗

粘贴进来的文本经常带噪声，检查项（都可单独开关，默认只开前两项）：

1. **路径方向**：`.\src\a\b.cpp` → `` `./src/a/b.cpp` ``（与 `fileReference()` 输出形状一致）。
2. **引号与破折号**：智能引号 `“”‘’` → 直引号；`—` → `-`（agent 命令行里常出问题）。
3. **行尾空白与多余空行**：去掉行尾空格、连续 3+ 空行压成 2 行。
4. **样式噪声**：从网页/Word 粘贴的多余缩进与项目符号层级。
5. **零宽字符**：清掉不可见字符（这类字符会让 agent 的 diff 看起来莫名其妙）。

- 清洗只在**粘贴**时执行，且给 undo 一步可回退；不做全局自动改写文件内容。
- 若清洗改变了内容，toast 说明改了什么（例如「已把 3 处反斜杠路径转成正斜杠」），否则用户会以为编辑器在乱改。

## 九、B8 自动配对与续行（P2）

- 反引号、括号、引号成对输入；在配对字符前再输入同字符则跳过而不是重复插入。
- 列表/任务清单回车自动续行；空列表项回车则退出列表。
- 这类输入法式改写容易与中文输入法冲突，**默认关闭**，放在设置或页内开关里。

## 十、B9 提示词体检（纯规则）

### 10.1 定位

结果落在**右侧属性区的「体检结果」段**（默认展开），逐条给**可点击**的建议（点了跳到编辑区对应位置）。
Ribbon 侧的入口是**提示词**标签页的**检查**Panel：`Check Prompt`（触发）、
`Checklist`（`InstantPopup` 逐条开关规则）、`Fix All Safe Issues`（只对机械项，见 §10.3）
——第 2 版原放「交付」页，交付页解散后迁入「提示词」页（见 `提示词撰写-09` D-2）。
不做评分、不打分等级——分数会诱导用户为分数写作，而清单能引导补全信息。
体检对象是**激活的草稿 tab**；文件 tab 上体检入口禁用（体检是提示词质量工具，
不是 Markdown 语法工具）。

### 10.2 规则草案（详细清单与阈值见 `提示词撰写-06`）

| 类别 | 触发 | 建议 |
|---|---|---|
| 过于笼统 | 命中「优化一下」「尽量」「看看」「等等」类模糊措辞 | 换成可验证的表述 |
| 求是而非求做 | 正文以疑问句为主且无祈使动词 | 写成明确指令 |
| 缺验收标准 | 没有出现测试/断言/期望结果类词汇 | 补一条「完成后运行什么、期望看到什么」 |
| 路径方向 | 检出 `.\foo\bar.cpp` 或裸 Windows 路径 | 一键改成 `` `./foo/bar.cpp` `` |
| 语言绑定 | 没提到任何语言/框架/文件 | agent 需要知道技术栈 |
| 上下文风险 | 粗略 token 估算超阈值 | 改用文件引用而不是内联整段内容 |
| 结构 | 长于 N 行的提示词没有任何标题/列表 | 建议分段，便于 agent 抓重点 |
| 占位符残留 | 正文里还有 `{{...}}` | 提醒还没填完 |

### 10.3 硬性边界

- **纯正则 + 启发式**，不联网、不调模型、不读用户项目内容之外的东西。
- 每条规则有稳定 id，可被单独关闭（用户会烦某一类提醒）。
- 规则命中位置必须能映射回编辑区区间（需要给 `MarkdownEdit` 加一个「跳到区间并选中」的入口）。
- 规则集是**可测的纯函数**：一句输入文本 → 一组 `{ruleId, severity, range, message}`。

## 十一、验收要点（补入 `提示词撰写-06` 的用例清单）

- 每个新格式化动作：空选区 / 单行选区 / 跨行选区三种输入的输出形状，以及「一次撤销即回退」。
- **光标处状态查询**：加粗/斜体/删除线/行内代码/标题级数在若干光标位置上的查询结果
  （Ribbon 的 `checkable` 按钮依赖它，必须有测试，否则按钮会骗人）。
- 围栏代码块带语言标注的输出形状。
- 查找：大小写开关、全词开关、回卷、全部替换计数。
- 清空与替换全文的超长内容保护（确认或可撤销）。
- 粘贴清洗：五种噪声各自的输入输出 + 「未改变内容时不提示」。
- 体检：每条规则的正例/反例各一，以及「命中区间能正确定位」。
