# C 组 · 上下文装配

> 索引见 `提示词撰写-00-总览与索引.md`；现状见 `提示词撰写-01`；
> 数据结构与上限见 `提示词撰写-06`、`提示词撰写-07`；
> **落点是统一工作台窗口 Ribbon「上下文」标签页 + 左侧文件树**（窗口与 tab 模型见
> `提示词撰写-12`，地图见 `提示词撰写-08` §2.2）。
>
> 这一组解决欠缺 **6（文件引用太浅）** 与 **7（不知道自己写了多长）**。
> 「装配」指：把一次任务需要的上下文（文件、区间、目录结构、日志、git 状态）高效地放进提示词，
> 而不是靠用户手打路径和整段粘贴。

## 一、功能表

| 编号 | 功能 | 优先级 | 一句话 |
|---|---|---|---|
| C1 | 带行号的引用 | **P0** | 文件可引用整个，也可只引用 `:120-140` 区间 |
| C2 | 多选批量插入 | P1 | 文件树 Ctrl/Shift 多选，一次插入引用清单 |
| C3 | 内联文件内容 | P1 | 右键「插入内容」→ 带文件名与语言的代码块（有上限） |
| C4 | 上下文预算条 | **P0** | 字符/行/粗略 token 估算 + 上下文占用可视化 |
| C5 | 目录骨架插入 | P2 | 只插结构不插内容的树形块 |
| C6 | 错误日志拖入 | P1 | 把日志拖进来，清洗成引用块并带上命令 |
| C7 | git 上下文插入 | P2 | 分支、`status`、`diff --stat` |
| C8 | 镜像/附件引用 | P2 | 截图或设计稿路径插入为引用 + 说明句 |

## 二、C1 带行号的引用

### 2.1 引用形状（建议）

| 场景 | 输出 |
|---|---|
| 整个文件 | `` `./src/tools/ToolsFacade.h` ``（**保持现状不变**，避免破坏既有习惯与已有草稿语义） |
| 区间 | `` `./src/tools/ToolsFacade.h:120-140` `` |
| 单行 | `` `./src/tools/ToolsFacade.h:120` `` |
| 整个目录 | `` `./src/tools/` `` |
| 多个文件 | 一行一个，或逗号分隔一行（由 C2 的插入方式决定） |

### 2.2 入口

1. **统一窗口的文件 tab 预览区**（整合后的主入口，即 E5「分节引用入草稿」）：在预览态选中
   若干行 → 上下文菜单或「上下文」标签页的 **Insert Reference into Draft** →
   生成区间引用并插到草稿（目标草稿规则见 `提示词撰写-12` §七）。这是最自然的路径：
   用户是在「看代码」的时候决定引用哪一段的。Ribbon 侧对应「上下文」标签页里的
   **Insert Reference into Draft** 与 **Open in Preview**（把当前文件 tab 切到预览态）。
2. **文件树右键** → 「引用整个文件」/「引用区间…」（后者弹一个起止行输入框，预填 1 与总行数）。
   Ribbon 侧对应「上下文」标签页 → 引用 Panel 的 `Insert File Reference` / `Line Range…` /
   `Insert Folder`。**同一动作在 Ribbon 与右键菜单各有一条入口是允许的**（同一处理函数、
   同一文案），但不要各写一份逻辑。
3. 从文件 tab 的预览态**拖选文本**进编辑区 → 生成区间引用（而不是把代码文本整段塞进去）。

### 2.3 边界与坑

- 预览会话属于 markdown 域，草稿属于 tools 域，插入动作是跨域——必须走
  工作台的意图入口（`提示词撰写-12` §八），QML 不自己拼路径。
- 行号必须是**该文件源文档的真实行号**（分块器的 `startLine/endLine` 与渲染 `<section>`
  一一对应，是预览域既有的锚；多会话化后每个会话各自持有分块结果，不串线）。
- 写进正文的始终是 `` `./相对路径:起-止` `` 这种**纯文本**形式，不引入只有本应用能解释的语法。

## 三、C2 多选批量插入

- 文件树支持 Ctrl 点选、Shift 连选；选中集合高亮。
- 一次插入的形态建议两种，按选中项数量自动选：
  - 少量（≤5）→ 一行一个引用；
  - 较多 → 一个带小标题的引用清单（`Related files:` + 列表）。
- 目录与文件混选时目录给 `` `./dir/` ``，文件给路径（或区间，若之前设过默认区间）。
- 需要扩展文件树模型/代理的选中集合状态；`ListView` 本身没有多选，需要自绘选中态
  （`required property` 的既有坑见 `提示词撰写-08`：delegate 的属性名必须与 role 名对应）。

## 四、C3 内联文件内容

### 4.1 适用与不适用

- **适用**：目标 agent 读不到本地文件（纯网页 agent、外部粘贴场景）、或文件很小、
  或要引用一段不能靠路径表达的内容。
- **不适用**：大文件（会把上下文吃光）。所以必须有上限，并且**超限时明确建议改用引用**，
  而不是截断后静默插入半份内容。

### 4.2 输出形状（建议）

```text
`./src/tools/ToolsStore.cpp` （第 1-60 行）
```cpp
...内容...
```
```

要点：

- 围栏语言取自文件后缀（**图标/后缀映射是数据不是代码**，可复用 `FileIcons` 已有的后缀表思路，
  或新增一张「后缀 → 围栏语言」的小表，同样放数据文件）。
- 必须带文件名与区间标题，否则 agent 不知道这段代码是什么、来自哪里。
- 行号可选（对 agent 定位有帮助，但会让 diff 变噪声）；默认关闭。

### 4.3 上限（建议值，可在决策中调整）

| 项 | 建议上限 | 超限行为 |
|---|---|---|
| 单文件内联 | 400 行 或 32 KB | 拒绝并建议改用区间引用或分段内联 |
| 一次内联总量 | 800 行 或 64 KB | 同上 |
| 非 UTF-8 / 二进制 | —— | 拒绝并说明原因（与预览域对非 UTF-8 的处理态度一致） |

## 五、C4 上下文预算条

- 位置：**中间文档区底部的一条状态条**（不占正文高度），同时右侧属性区给一段可展开的明细。
  Ribbon 侧在**草稿**标签页的统计 Panel 放一个只读文本容器（`RibbonControlContainer`），
  以及 Context Window 设置（`InstantPopup`）。
- 显示：字符数、行数、**粗略 token 估算**、以及一个相对常用上下文窗口的占用条。
- **草稿与文件共享状态条**：文件 tab 显示同一估算函数的「文档版统计」（E6，
  见 `提示词撰写-12` §一），预算占用条只在草稿 tab 出现（占用条回答「这条提示词会不会
  撑爆上下文」，对别人的文档无意义）。
- **诚实性硬要求**：界面上必须写明这是估算，且不承诺与实际分词器一致。措辞与 `guide/` 文案都要交代，
  否则会变成误导功能。
- 估算公式与阈值见 `提示词撰写-06`。
- 颜色分级用主题语义令牌（安全/提醒/超限），**不写字面颜色**。
- 可选交互：点击预算条 → 弹出明细（哪些段落占用最多、内联内容共占多少）。

## 六、C5 目录骨架插入（P2）

- 右键目录 → **Insert folder outline** → 插入仅含结构（目录 + 文件名，不含内容，带缩进）的代码块。
- 常用于「让 agent 先了解项目结构」。默认深度上限 3 层、条目上限 200 行，超限提示。
- 与内联内容一样需要避让：骨架不替代引用，只是导览。

## 七、C6 错误日志拖入（P1）

- 场景：终端/构建窗口/日志文件里的报错要交给 agent 修。
- 交互：从终端或日志视图拖文本进编辑区 → 插入为**引用块**，去掉 ANSI 颜色转义与时间戳噪声，
  并在上方自动补一行「要执行的命令 + 期望」的提示句（可关）。
- 也支持从文件树拖 `.log` 文件时选择「引用文件」还是「内联最后 N 行」。
- 清洗规则复用 B7 的思路，但针对日志做专门处理：ANSI 转义、重复行合并、路径反斜杠。

## 八、C7 git 上下文插入（P2）

- 右键菜单：
  - 插入当前分支名（内置变量 `{{branch}}` 的自然延伸）；
  - 插入 `git status` 摘要；
  - 插入 `git diff --stat`（不是完整 diff，避免吃光上下文；要完整 diff 时走「让 agent 自己跑」）。
- 实现路径：一次性命令统一走既有的 `core::ScriptRunner` 通道（输出实时可见、可取消），
  **不要新造进程执行路径**。命令失败时给可展示原因，不静默插入空块。
- 需要明确：这些命令在**当前工作区**目录下执行。

## 九、C8 镜像 / 附件引用（P2）

- 截图或设计稿的路径插入为引用 + 一句说明（「设计稿见 …」）。
- **不做上传、不做图片编码内联**（那会极大占用上下文，且多数 agent CLI 读不了）。
- 若将来某个 agent 明确支持图片路径，再单独讨论。

## 十、验收要点（补入 `提示词撰写-06` 的用例清单）

- 引用形状：整文件 / 区间 / 单行 / 目录 / 多文件，各自输出与 `fileReference()` 现有形状的兼容性
  （整文件必须与今天逐字节一致）。
- 内联：正常文件、超单文件上限、超总量上限、非 UTF-8、空文件。
- 预算：纯 ASCII、纯中文、混合、超长草稿的估算稳定性（同样输入同样输出）。
- 目录骨架：深度上限与条目上限。
- 日志清洗：ANSI 转义、重复行、反斜杠路径。
- git 插入：命令失败时的行为（不插入空块 + 可展示原因）。
- 分节引用（E5 联动）：目标草稿三态（激活草稿 / 激活文件 tab / 无草稿）各自路径；
  相对路径按目标草稿的工作区计算。
