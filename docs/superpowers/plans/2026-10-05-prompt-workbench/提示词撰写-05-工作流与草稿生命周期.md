# D 组 · 工作流与草稿生命周期

> 索引见 `提示词撰写-00-总览与索引.md`；现状见 `提示词撰写-01`；决策记录见 `提示词撰写-09`；
> **落点是统一工作台窗口 Ribbon「草稿」标签页 + 中间区顶部的文档 tab 条**（窗口与 tab 模型见
> `提示词撰写-12`，地图见 `提示词撰写-08` §2.2）。
>
> 这一组解决欠缺 **4（没有多任务）**、**9（跨会话不可靠）**、**10（草稿与工作区脱钩）**。
> 原第 2 版的 D4（目标 agent 绑定）与 D5（发送到 agent）已**整体移出规划**
> （决策 D-1）：本窗口不存在任何发送路径，回车只换行，交付只有复制——
> 这条产品主张从「页面级」升级为「窗口级」，比第 2 版的「默认关闭」更强。

## 二、D1 多草稿

### 2.1 形态

- **草稿并入统一文档 tab 条**（M4，决策 D-3 第二步）：草稿 tab 与文件 tab 混排，
  用小徽标（`APill` 形态）区分来源；文件 tab 显示文件名，草稿 tab 显示草稿标题；
  脏标记沿用编辑区现有语义。
- Ribbon「草稿」标签页承载草稿的**管理动作**：`New Draft`、`Rename`、`Duplicate`、`Close`、
  `Delete`——Tab 条只负责切换与新建。
- 标题来源：首行（去 markdown 记号）自动截取；用户可重命名；空草稿显示「Untitled」。
- 每条草稿记住：标题、正文、绑定工作区、创建/更新时间（`targetAgent` 字段已随 D-1 删除）。
- 上限建议 20–50 条（与工作区上限同一量级），超出时提示而不是静默淘汰；
  **被淘汰的永远是空草稿或最久未编辑的，且要提示**。
- 关标签 ≠ 删草稿：关掉草稿 tab 只是移出 tab 条，仍可在「草稿历史」段与 `History` 弹层里找回
  ——与文件 tab 的「关 = 关视图不删文件」同一语义（`提示词撰写-12` §3.1）。

### 2.2 与文件树、模板库的关系

中间区顶部的文档 tab 条与**左侧属性区**是两回事：左侧区放素材（文件树、模板库、收藏夹），
tab 条属于编辑区。左侧区三段纵向堆叠、可分别折叠（见 `提示词撰写-08` §1.1），
**默认展开文件树**，不改变老用户「进来先看文件树」的肌肉记忆。
切草稿时文件树跟着切到该草稿的工作区（D3）——树是侧栏内容，不随 tab 销毁。

## 三、D2 草稿历史与快照

- 快照触发点（建议）：
  1. 复制到剪贴板时（说明这一版是「用过的一版」）；
  2. 清空 / 替换全文之前（自动存旧内容）；
  3. 切换草稿、关闭应用前（有改动才存）；
  4. 用户手动「存一版」。
- 快照内容：正文 + 时间 + 触发原因 + 字数。默认保留最近 30 版或 7 天，二者先到为准。
- 历史面板：列表 → 选中给**只读预览** → 三个动作：**回滚到这一版**（回滚本身也存一版，
  保证可再撤回）、**复制这一版**、**删除这一版**。
- 不做「diff 两版」的完整工具（P2 可加行级差异高亮）；第一版只需预览 + 回滚。
- 与编辑区自身的撤销栈分工明确：撤销栈管「本次会话的按键级回退」，快照管「跨会话的版本级回退」。

## 四、D3 草稿 ↔ 工作区关联

- 每条草稿带 `workspace` 字段：切草稿时文件树跟着切到该草稿的工作区（不存在则树为空并提示）。
- 切工作区时**不静默改动**当前草稿内容；给一个明确选择：「把当前草稿归到这个工作区」还是
  「新建一条挂在这个工作区的草稿」。
- 兼容：旧的单一 `draft` 键在首次加载时视作「一条默认草稿」，工作区绑定为旧的 `current`。
  **这必须是读侧容错，不是迁移代码**（项目明确不写 settings/agents 类迁移；`tools.json` 同理）。

## 五、D6 崩溃 / 强杀恢复入口

- 现状：只有 500 ms 防抖 + 析构补写，崩溃或强杀会丢最后一次编辑。
- 方案：在**编辑期间**额外写一份轻量恢复副本（比草稿正文的写盘节奏更密，但仍是降频写，
  不要每次按键都写盘），进程正常退出时清掉它。
- 启动时若发现恢复副本存在（说明上次没正常退出）→ 一次性提示：「上次未正常退出，
  发现 X 字未归档内容：恢复 / 丢弃」。
- 恢复动作：把内容变成一条新草稿（不覆盖现有内容），并在标题上标注来源。
- 参照仓库现有的「首次启动 legacy 导入提示一次」的做法（`core::LegacyImport::runOnce` +
  一次性提示），保持交互形态一致。
- 与 E3 会话恢复是两件事：恢复副本救的是「没来得及写盘的正文」，会话恢复找回的是
  「上次开着的 tab 组」——前者按草稿、后者按窗口（`提示词撰写-07` §二分列两键）。

## 六、D7 启动行为与空草稿引导（P1）

- 现状：启动时工作区来自上次的 `current`，草稿来自上次的 `draft`。真正的问题是
  **没有多条草稿时的入口感**：用户看到空编辑区不知道从哪开始。
- 窗口整合后的启动结构（决策 D-10）：应用启动**不自动开工作台窗口**（启动页承载入口）；
  用户开窗时**恢复上次 tab 组**（E3）；「启动时自动打开工作台」是设置开关（默认关）。
  本组只负责剩下的**空草稿引导**：
  - 空草稿时中间区给**起步引导**（不是空白）：三个动作——选模板（跳 Ribbon「提示词」页）、
    从最近草稿继续、直接写；
  - 右侧属性区的「草稿历史」段默认就列出**最近草稿**（按时间倒序，带工作区路径与字数）；
  - 启动页的「最近草稿」列表与本段同数据源（`提示词撰写-12` §1.2）。

## 七、D8 窗口级快捷键（P1）

| 快捷键 | 动作 | 备注 |
|---|---|---|
| Ctrl+N | 新建草稿 | 与「清空」区分开 |
| Ctrl+F | 查找 | B2 |
| Ctrl+S | 存为模板 | A3（不是「保存草稿」——草稿自动保存；文件 tab 上是「保存文件」）。注意 ribbon 的 `RibbonMenuItem.shortcut` 只是显示字段，真正的绑定要在 `Shortcut` 里写，两处文案必须一致 |
| Ctrl+W | 关闭当前 tab | 文件/草稿同语义（关视图不删内容） |
| Esc | 关查找条 / 关面板 | —— |
| `?` | 快捷键面板 | B4 |

- **没有 Ctrl+Enter 发送**——发送功能不存在（决策 D-1），快捷键表里也不预留它的位置：
  预留的绑定会诱导后来人把它实现出来。
- 加绑定前先确认与全局快捷键、与 `TextArea` 内建快捷键不冲突（仓库里的
  「QML 要调用的方法必须 `Q_INVOKABLE`」这条契约同样适用于快捷键处理器调到的槽）。
- **Ribbon 按钮上的 `shortcut` 只是显示，不会真的注册快捷键**：`RibbonMenuItem.shortcut` 是文案字段
  （用于在菜单里显示 Ctrl+S 这类提示），真正的按键处理要在窗口的 `Shortcut` 里写，
  并**同时**把同一串文案填进 `RibbonMenuItem.shortcut`，否则两处会不一致。
  这也意味着快捷键清单必须集中在一处（建议窗口级一个 `Shortcut` 区块 + 一份共用的文案表）。

## 八、验收要点（补入 `提示词撰写-06` 的用例清单）

- 多草稿：新建/切换/重命名/删除；上限行为；切换后文件树是否跟着走；与文件 tab 混排的徽标区分。
- 历史：触发点是否都产生快照；回滚后能否再撤回；上限淘汰顺序。
- 兼容：只有旧 `draft` + `current` 的 `tools.json` 能被正确读成一条默认草稿；读后写回不丢数据。
- 恢复：模拟「有恢复副本 + 正常启动」和「无副本 + 正常启动」两条路径。
- 关联：草稿的工作区被删掉后切到该草稿的表现（树空 + 提示，不崩溃）。
- **发送不存在**：全窗口 QML 与门面断言里没有任何发送/agent 注入入口（防回归——
  把「不发送」当成一条要测的规格，而不是「没做」）。
