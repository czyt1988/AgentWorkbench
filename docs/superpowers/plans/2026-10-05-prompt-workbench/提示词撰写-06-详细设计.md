# 详细设计

> 索引见 `提示词撰写-00-总览与索引.md`。
> 本文是 A/B/C/D 四组的**字段级细化**：数据结构、解析规则、体检规则、估算公式、验收用例清单。
> 类名与文件名为**建议落点**，实现时可以改名，但层次归属（见 `提示词撰写-08`）不能变。

## 一、数据结构

### 1.1 建议新增的模块内类型

| 建议类型 | 归属 | 职责 |
|---|---|---|
| `PromptTemplate` | `src/tools/`（值类型） | 一份模板：id / title / category / tags / description / body / variables / scope |
| `PromptTemplateLibrary` | `src/tools/` | 三层来源合并（内置 + 用户 + 用户改写内置）、检索、标签过滤、插入求值 |
| `PromptDraft` | `src/tools/`（值类型） | 一条草稿：id / title / body / workspace / createdAt / updatedAt（**无 targetAgent**，已随 D-1 删除） |
| `DraftHistory` | `src/tools/` | 快照的追加、上限淘汰、读取、回滚 |
| `PromptChecks` | `src/tools/`（纯函数） | 文本 → `{ruleId, severity, range, message}` 清单 |
| `ContextBudget` | `src/tools/`（纯函数） | 文本 → 字符/行/粗略 token 估算与分级（草稿预算条与文件 tab 统计共用，E6） |
| `PromptsStore`（或扩展现有 `ToolsStore`） | `src/tools/` | 上述状态的磁盘读写 |
| `MarkdownSessionStore` | `src/workbench/`（或 markdown 域，见 `提示词撰写-12` §八） | 窗口会话的序列化：tab 清单、激活位、双预设的界面状态、最近文档 MRU |
| `PromptFormatting`（或在 `MarkdownEdit` 上补查询侧） | `src/tools/` | 「光标处是否已加粗 / 是第几级标题 / 是否在列表里 / 是否在代码块里」的 `Q_INVOKABLE` 查询——Ribbon 的 `checkable` 按钮靠它，**没有它就不要设 `checkable`** |
| `MarkdownBookmarks` | `src/markdown/`（E7，P2） | 标题/块级锚的书签与本地高亮存取（见 `提示词撰写-07` §四） |

倾向**扩展现有 `ToolsStore`** 而不是新建一个平行的 store：`tools.json` 是同一个文件的同一份状态，
两个 store 写同一个文件会互相覆盖。

### 1.2 草稿字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定标识（生成一次，永不变） |
| `title` | string | 用户可改；空时由首行推导 |
| `body` | string | 正文（Markdown） |
| `workspace` | string | 绑定的工作区绝对路径；空串 = 未绑定 |
| `createdAt` / `updatedAt` | 数字（毫秒时间戳） | 排序与「最近草稿」用 |
| `pinned` | bool | 可选：固定不被上限淘汰 |

（原 `targetAgent` 字段删除——D4 已移出规划，`tools.json` 从未写过这个键，无兼容负担。）

### 1.3 快照字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `draftId` | string | 属于哪条草稿 |
| `body` | string | 那一版正文 |
| `reason` | enum 字符串 | `copy` / `clear` / `replace` / `switch` / `manual` / `rollback` |
| `createdAt` | 数字 | 时间 |
| `charCount` | 数字 | 便于面板显示（避免每次都数） |

## 二、模板解析与变量求值

### 2.1 变量语法（正则草案）

| 形式 | 匹配 |
|---|---|
| 变量 | `\{\{\s*([A-Za-z_][A-Za-z0-9_]*)\s*(?::\s*([^}]*))?\s*\}\}` |
| 包含 | `\{\{>\s*([^}]+?)\s*\}\}` |

- 变量名限定 ASCII 标识符（避免中文名带来的编码歧义）。
- 求值顺序：先展开包含（深度上限 5，检出循环报错），再替换变量。
- 内置变量：`workspace`（当前工作区）、`date`（本地日期）、`branch`（当前分支，取不到则留空并提示）、
  `selection`（插入瞬间编辑区的选区）。
- 逃逸：`{{{{` 输出字面 `{{`（若实现成本高可先不做，但要在文档里说明不支持）。

### 2.2 变量提取规则（A3 存为模板用）

1. 正文中形如 `` `./...` `` 或 `` `...` `` 且看起来是路径的片段 → 提议转成 `{{file}}`。
2. 出现 2 次以上、长度 ≥ 3 的英文/中文专有名词 → 提议转成 `{{name}}`（最多提议 5 个，避免刷屏）。
3. 提议是**逐条可接受/忽略**的，不做静默替换。

### 2.3 变量填充后的收尾

- 未填变量：正文保留 `{{原样}}`，并在编辑区高亮为待办色（高亮由 `MarkdownEdit` 的规则追加一条）。
- 已填变量：替换为纯文本；对路径类变量按 B7 的路径规范化处理。

## 三、提示词体检规则清单

每条规则：`id` / 严重度 / 触发条件 / 建议文案（英文源串，可翻译）/ 是否可跳转。

| id | 严重度 | 触发条件（草案） | 建议 |
|---|---|---|---|
| `vague-wording` | 提醒 | 命中 `优化一下`/`看看`/`尽量`/`等等`/`最好` 等模糊词表（中英各一份） | 换成可验证的表述 |
| `question-only` | 提醒 | 以 `?`/`？` 结尾的句子占比 > 50% 且全文无祈使动词 | 写成明确指令 |
| `no-acceptance` | 警告 | 无任何验收类词汇（测试/断言/期望/通过/verify/test/expect） | 补一条「完成后运行什么、期望看到什么」 |
| `backslash-path` | 警告 | 命中 `.\` 或裸盘符路径 | 一键改成 `` `./正斜杠` `` |
| `no-context` | 警告 | 全文无语言/框架/文件名/路径 | agent 需要知道技术栈与落点 |
| `token-risk` | 警告 | 粗略估算超过阈值（见 §四） | 改用文件引用而非内联整段内容 |
| `flat-structure` | 提示 | 行数 > 40 且没有任何标题/列表 | 分段，便于 agent 抓重点 |
| `unfilled-placeholder` | 提醒 | 正文里仍有 `{{...}}` | 占位符还没填完 |
| `trailing-whitespace` | 提示 | 存在行尾空白或 3+ 连续空行 | 可选一键清理（与 B7 共用） |
| `smart-quotes` | 提示 | 存在智能引号或破折号 | 可选一键替换（与 B7 共用） |

规则设计要求：

- **纯函数**：同输入同输出，无 IO、无网络、无模型。
- 可单独开关（用户会烦某一类），开关状态持久化。
- 命中区间必须能映射回编辑区（需要 `MarkdownEdit` 暴露「选中区间并滚动到可见」）。
- 词表放数据文件而不是硬编码在 .cpp 里（与 `default_file_icons.json` 同惯例，便于用户扩充）。

## 四、上下文预算估算

### 4.1 公式（草案，必须标注为估算）

```
估算 token ≈ ASCII 字符数 / 4 + 非 ASCII 字符数 × 0.9
```

- 只是为了给量级感，**不承诺与任何具体分词器一致**。
- 同样输入必须同样输出（纯函数，可测）。
- 界面文案示例：「约 1,240 tokens（估算）」；`guide/` 里也要说明这是粗略估算。

### 4.2 分级

| 级别 | 阈值（建议，可配置） | 表现 |
|---|---|---|
| 安全 | < 上下文窗口的 25% | 中性色 |
| 提醒 | 25% – 60% | 注意色 |
| 超限 | > 60% | 警示色 + 提示改用引用 |

上下文窗口默认值取一个保守常量（例如 32k），并允许用户在设置里改；不尝试探测目标 agent 的真实窗口
（探测不到，猜错比不猜更糟）。

## 五、文件引用的最终形状（与现有实现的关系）

| 场景 | 输出 | 与现状关系 |
|---|---|---|
| 整文件（拖拽/双击/右键） | `` `./src/a/b.cpp` `` | **必须与今天逐字节一致**，否则所有已有草稿的语义与用户习惯被打破 |
| 行区间 | `` `./src/a/b.cpp:120-140` `` | 新增 |
| 单行 | `` `./src/a/b.cpp:120` `` | 新增 |
| 目录 | `` `./src/a/` `` | 新增（尾斜杠） |
| 多文件清单 | 一行一个，或 `Related files:` + 列表 | 新增 |
| 内联内容 | 标题行（路径 + 区间）+ 带语言的围栏代码块 | 新增，有上限 |

行号的正负号与区间分隔符建议固定用 `:起-止`，不要引入 `:` 与 `-` 之外的约定。

## 六、验收用例清单（建议进 `tests/tools/`）

按「纯层优先」的组织方式：不依赖网络、不依赖本机已安装 agent、不读写真实数据目录。

### 6.1 存储与兼容（`tst_tools`）

1. 只有 `workspaces`/`current`/`draft` 的旧 `tools.json` → 读成一条默认草稿，工作区绑定 = `current`，
   正文 = `draft`；写回后旧键仍存在且内容一致。
2. `tools.json` 缺失 / 损坏 → 空状态，不崩溃。
3. 多草稿增删改与上限淘汰；被淘汰的是空草稿/最久未编辑且给出提示。
4. 快照：四个触发点各产生一版；上限淘汰顺序；回滚后可再撤回。
5. 恢复副本：存在/不存在两条启动路径。

### 6.2 模板与变量

6. 三层合并顺序：内置 → 用户 → 用户改写内置（改写者胜出）。
7. 变量：同名多次全替换、带默认值、未填保留原样、内置变量求值。
8. 包含：正常展开、超过深度上限、循环包含报错而不死循环。
9. 存为模板：首行取标题、路径提议转变量、写入目录后立即可见。

### 6.3 编辑动作（纯 `QTextDocument` 驱动）

10. 每个格式化动作 × 三种输入（空选区 / 单行选区 / 跨行选区）；一次撤销即回退。
11. 围栏代码块的语言标注输出形状。
12. 查找：大小写开关、全词开关、回卷、全部替换计数。
13. 粘贴清洗：五类噪声的输入输出；内容未变时不提示。
14. 长内容保护：清空/替换全文的确认或可撤销路径。
14b. **光标处状态查询**（Ribbon `checkable` 按钮的数据源）：加粗/斜体/删除线/行内代码/
     标题级数/是否在列表里/是否在围栏代码块里，各在若干光标位置上的查询结果。

### 6.4 体检与预算

15. 每条规则（§三的表）正例 + 反例各一。
16. 命中区间能正确映射回编辑区并选中。
17. 预算估算：纯 ASCII / 纯中文 / 混合 / 超长；同输入同输出；分级阈值边界。

### 6.5 界面冒烟（`tests/tools/tst_toolsui.cpp` 传统 + 窗口迁移后的平移）

18. 新增面板都给稳定 `objectName`，并断言：模板插入、变量表单出现与消失、查找条打开与关闭、
    体检面板条目点击后编辑区选中区间。
19. `Checklist`：任何新增的 QML 要调用的 C++ 方法/属性必须 `Q_INVOKABLE`/有 `WRITE`
    且被冒烟覆盖（仓储既有红线的来源，见 `提示词撰写-08`）。
20. 显式绑定与动作落点检查：**每个窗口动作都能在窗口 QML 里找到唯一的一处出口**
    （Ribbon 按钮、侧栏按钮或右键菜单三者之一），不允许同一动作有两份实现。
21. **Ribbon 相关的测试要分两档**（第三方 C++ 宿主创建的控件 `objectName` 不一定可控，
    且 `AWB_ENABLE_RIBBON` 有开/关两种构建）：
    - **可测**：门面状态、`MarkdownEdit` 的纯函数与查询接口、`tools.json` 的读写——与 UI 框架无关，照常测；
    - **不宜直接点击**：ribbon 按钮的点击。做法是把按钮背后的动作暴露成窗口/门面的 `Q_INVOKABLE`，
      测那一层；真要对「按钮接对了没有」做覆盖时，用 `RibbonToolButton.click()`（它本身是
      `Q_INVOKABLE`），或对 `RibbonCategory.title` / `RibbonPanel.panelTitle` 做结构断言，
      而不是依赖 `objectName` 查找；
    - 关闭 `AWB_ENABLE_RIBBON` 的构建里，上述 ribbon 相关断言必须整体跳过而不是失败。

### 6.6 窗口整合与文件关联（E 组，`tests/workbench/` 新增或并入 `tst_markdownpreview` 家族）

22. 模式预设：提示词预设开窗默认侧栏全开；文档预设默认收起 + Ribbon 折叠；
    两套界面状态互不污染（切换后各自记住）。
23. 统一编辑器：文件 tab 的源码区有高亮、格式动作可用（驱动 `MarkdownEdit` 后断言文档内容）；
    保存字节保真（`tst_markdown` 既有用例平移不删）。
24. tab：文件/草稿混排、徽标区分、关闭语义（文件视图关/草稿找回）、上限提示。
25. 会话：正常关窗 → 重开恢复 tab 组与激活位；文件丢失 → 空态 tab；草稿被删 → 跳过；
    「启动时自动打开」开关两态。
26. 文件关联：argv 单文件/多文件（`main` 的参数解析纯函数化后直接测）；
    单实例 open 消息解码与分发；注册动作成功/失败两路；无能力构建的报因路径。
27. 从文档新建草稿：全文复制、标题与工作区绑定规则（在/不在 `workspaces` 列表两分支）、单向无关联。
28. 分节引用：目标草稿三态（激活草稿 / 激活文件 tab / 无草稿）；行号与选区映射正确
    （选区 → 源行区间的纯函数单测）；相对路径按目标草稿工作区计算。
29. **发送不存在**（防回归规格）：窗口 QML 全量扫描无发送类动作；`WorkbenchContext`
    意图方法清单不含 agent 注入类入口。
30. 书签/高亮（若实施）：锚定在编辑后不漂移（插入/删除行后块锚稳定）；文件移动后失配标灰不删；
    存储文件不含在 .md 本体上写任何字节的路径。

## 七、清单：实现每一项时都要问的问题

- 它是否让「不发送」这条主张变得模糊？如果是——停下来，这个功能不该做（决策 D-1，
  见 `提示词撰写-09`），文档与文案也不许为它开口子。
- 它是否引入网络调用？如果是，归到 A8 并等决策。
- 它是否新增磁盘键？如果是，走「只加不改不删 + 读侧容错」。
- 它是否跨域（tools / markdown / web）？如果是，走工作台意图入口。
- 它的入口是不是**重复**的（Ribbon 里已有、侧栏又想加一个）？如果是，二选一。
- 它是不是需要在 ribbon 里弹窗？如果是，必须走 `Loader` 惰性创建（见 `提示词撰写-11` §四.2）。
- 它是否需要 `checkable`？如果是，先确认有真实的光标处状态源。
- 它的纯逻辑部分能否脱离 QML 单独测？如果否，先拆出来。
