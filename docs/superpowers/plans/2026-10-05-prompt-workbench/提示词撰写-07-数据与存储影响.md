# 数据与存储影响

> 索引见 `提示词撰写-00-总览与索引.md`；字段定义见 `提示词撰写-06`；窗口与文件关联的
> 功能语义见 `提示词撰写-12`。
>
> 本文只回答「磁盘上多了什么、旧数据怎么办」。核心原则一句话：
> **只加键，不改名，不删键，不写迁移代码。**

## 一、磁盘布局（现状 → 规划）

| 路径 | 现状 | 规划后 |
|---|---|---|
| `<dataRoot>/tools.json` | `workspaces` / `current` / `draft` | 上述三键**保持不变**，新增键见 §二 |
| `<dataRoot>/prompt_templates/` | 无 | 用户模板与片段（每模板一个文件） |
| `<dataRoot>/prompt_favorites.json`（或并入 `tools.json`） | 无 | 收藏夹 |
| `<dataRoot>/tools_recovery.json` | 无 | 编辑期间的崩溃恢复副本（正常退出时删除） |
| `<dataRoot>/markdown_session.json` | 无 | 工作台窗口会话：tab 清单、激活位、双预设界面状态、最近文档 MRU（E3） |
| `<dataRoot>/markdown_bookmarks.json` | 无 | 书签与本地高亮（E7，P2；标题/块级锚，不写回 .md） |
| `config/default_prompt_templates.json` | 无 | 内置模板，随包只读 |
| `config/prompt_check_words.json` | 无 | 体检词表（模糊词、验收词等），可被用户覆盖 |

三点说明：

1. **收藏夹建议并入 `tools.json`**（体量小、与草稿同生命周期、少一个文件少一处失败点）；
   模板则独立成目录（体量大、用户要手改、要能单独备份分享）。
2. 内置数据文件一律走「内置随包 + 用户覆盖」的既有惯例（`default_agents.json`、
   `default_file_icons.json` 都是这个形状）。**不要在 C++ 里硬编码模板或词表条目。**
3. **两类「恢复」分开存**：`tools_recovery.json` 救「没写盘的草稿正文」（按草稿，
   D6）；`markdown_session.json` 找回「上次开着的 tab 组」（按窗口，E3）。
   一个管内容、一个管布局，键位与淘汰策略互不相干，**不要合并成一个文件**。

## 二、`tools.json` 键位扩展

### 2.1 新旧键并存

| 键 | 状态 | 说明 |
|---|---|---|
| `workspaces` | **不变** | 工作区 MRU 列表 |
| `current` | **不变** | 当前工作区 |
| `draft` | **保留** | 旧字段。首次读入时视作「默认草稿」的正文；此后继续同步为「当前草稿正文」，避免旧版本回退读时丢内容 |
| `drafts` | 新增 | 草稿数组，见下 |
| `activeDraftId` | 新增 | 当前草稿 id |
| `favorites` | 新增 | 收藏数组 |
| `checks` | 新增 | 体检规则开关：`{ruleId: bool}`（或「已关闭的规则 id 数组」） |
| `editor` | 新增 | 编辑偏好：打字机模式、粘贴清洗开关、自动配对、变量占位高亮 |
| `ribbon` | 新增 | Ribbon 自己的界面状态：`collapsed`（折叠）、`style`（单行/两行/三行）、`followAppTheme`、`lastTabIndex` |

`drafts` 数组每项：`id` / `title` / `body` / `workspace` / `createdAt` / `updatedAt`
（**无 `targetAgent`**——D4 已移出规划，从未落盘，无兼容负担）。

**`ribbon` 这一项要留在 `tools.json` 里**，不要让 SARibbon 自己存到别处：
- SARibbon 的运行时自定义（`RibbonCustomizeDialog` / `RibbonActionRegistry`）产出的是它自己的
  自定义记录序列化，那是**另一份数据**——但第一版不启用该功能（决策 D-9），无落盘；
- 本项目真正需要持久化的只有「折叠状态、样式、是否跟随应用主题、上次停留的标签页」这四个小值，
  它们是**窗口的界面偏好**，属于 `tools.json` 的职责范围。

### 2.2 兼容读取策略（替代迁移代码）

首次加载时：

1. 若 `drafts` 不存在或为空，且 `draft` 非空 → 建一条默认草稿：正文 = `draft`，
   工作区 = `current`，id 固定为 `"default"`（稳定 id 让旧配置可预期）。
2. 若 `drafts` 已存在 → 以其为准；`draft` 只是「当前草稿正文」的镜像。
3. 未知键忽略并记一条警告（与 `core::Settings` 的既有态度一致）。
4. 任何键缺失都取默认值，**不报错、不弹窗**。

不变量（实现时要保证、测试要覆盖）：

- `activeDraftId` 必须指向 `drafts` 中真实存在的一项；指向不存在项时回退到第一项（或新建一条空草稿）。
- 每条草稿的 `workspace` 要么为空串，要么是一个字符串（**不要求它仍在 `workspaces` 列表里**——
  列表有 20 条上限，草稿的工作区可能已被淘汰，此时文件树显示为空并提示即可）。
- `body` 与旧 `draft` 镜像不一致时以 `drafts` 为准（`drafts` 是权威源）。

### 2.3 写盘节奏

| 内容 | 节奏 |
|---|---|
| 草稿正文 | 沿用 **500 ms 防抖 + 析构补写**（不要退化成每次按键写盘） |
| 崩溃恢复副本 | 比草稿更密但仍是降频（例如 2 s 或「停顿 1 s 后」），**只写当前草稿正文** |
| 结构类变更（增删草稿/收藏/模板/开关） | 立即写 |
| 会话（tab 结构、激活位、预设） | tab 结构变化时立即；视图态跟随既有防抖节奏 |
| 文件 tab 的保存 | 用户显式动作，字节保真（预览域既有语义，不进 `tools.json`） |

仓库已有 `core::JsonStore` 的原子写（临时文件 + 替换），全部状态都走它，不要自己拼 `QFile` 写入。

## 三、模板目录形态

### 3.1 一个模板一个文件（推荐）

- 位置：`<dataRoot>/prompt_templates/`，文件名即 id 的可见形式（例如 `fix-a-bug.md`）。
- 形态：Markdown 正文 + 头部字段（标题、分类、标签、描述、适用范围）。
- 好处：用户能手改、能进 git、能单独拷给同事、坏一个文件不影响其它模板（读不了的条目跳过并记警告）。
- 载体格式上，仓库里 skill 用的是 front-matter 风格；但**`awb_tools` 不能依赖 skill 域**
  （模块间零依赖，见 `提示词撰写-08`），所以这里需要在本模块内自带一个**最小**头部解析器，
  只支持「分隔线 + `键: 值`」这一层，不实现通用 YAML。

### 3.2 内置模板文件

- `config/default_prompt_templates.json`，与内置 agent 同惯例：
  **与默认完全一致时写回逐字节不变**（便于 diff），用户新增/改写不会被随包更新覆盖。
- 命名与 id：内置条目 id 稳定（例如 `builtin-fix-a-bug`），改名等于用户对它的改写丢失。

## 四、会话与书签（E 组新增）

### 4.1 `markdown_session.json`（E3 会话恢复 + MRU）

- 内容：tab 清单（`{kind: file|draft, path|draftId}` + 每 tab 的视图态）、激活 tab 索引、
  窗口的双预设界面状态（侧栏折叠、Ribbon 折叠、三态）、最近文档 MRU（前 20 条）。
- 归属：会话是**窗口级布局状态**，跨 tools（草稿 id）与 markdown（文件路径）两个域，
  由 workbench 域持有与读写（`MarkdownSessionStore`，见 `提示词撰写-06` §1.1）。
- 写盘：tab 结构变化立即、视图态防抖；**正常退出不删除**（会话的意义就是跨启动找回）。
- 失配处理：文件不存在 → 该 tab 恢复为空态占位；草稿 id 被删 → 跳过该 tab；
  JSON 损坏 → 整体作废重来（布局状态不值得抢救），记一条警告。
- 隐私口径：只有本地路径与草稿 id，无正文；不加密、不清理（`提示词撰写-12` §6.2）。

### 4.2 `markdown_bookmarks.json`（E7，P2）

- 内容：按文件绝对路径分组；每组一组书签/高亮 `{块级锚, 颜色/标签, 创建时间}`。
  锚是**标题/块级锚**（决策 D-11）：块索引 + 块首行文本摘要（双保险，块索引漂移时用文本再定位）。
- 归属：markdown 域（锚的语义依赖分块器）；**写入目标只有这个 JSON**，
  任何路径都不指向 .md 本体（用例 30 验证两个路径集合无交集）。
- 失配处理：文件移动后路径对不上 → 该组标灰（保留数据、不可导航），不做「自动追踪移动」；
  块结构变了 → 用块首文本重定位，找不到就把该书签标灰。
- 上限：每文件 50 条、全局 500 条，超出提示。

## 五、备份、导出与体积

- 用户模板目录 + 收藏夹构成「我的提示词资产」，导出（A7）就是打包这两块。
  （会话与书签**不进导出**——它们是本机布局/查阅状态，不是资产。）
- 体积估算：模板几十条 × 数 KB、收藏几十条 × 数 KB、草稿 50 条 × 数 KB、快照 30 版 × 数 KB、
  会话与书签数 KB → 总量在百 KB 到数 MB 量级，**不需要分库或压缩**。但要在文档里给上限值，避免无限增长。
- 清理入口：设置或面板里给「清理历史快照」「清理空草稿」两个动作，删除前给条数与体积。

## 六、与既有数据的边界（不要碰的东西）

- `settings.json`、`agents.json`：本规划**不改**（「启动时自动打开工作台」开关按既有
  settings 键惯例新增，走 `core::Settings` 的结构体，不改已有键）。
- **工作区目录内的任何文件：只读**——唯一例外是文件 tab 的**用户显式保存**（预览域
  既有语义，写字节保真，不是本规划新增的写路径）与书签存储**绝不**指向工作区文件。
- `~/.AgentLauncher` 旧数据：由既有的 `core::LegacyImport` 一次性复制处理，本规划不新增迁移来源。
- **注册表（文件关联）**：HKCU 的 ProgId + OpenWithProgids 两个键（E2），
  由设置页动作显式写入；不写其它任何注册表位置；卸载不清理（见 `提示词撰写-12` §5.2）。

## 七、验收要点

- 旧 `tools.json`（只有三个键）读入 → 内容全部保留；写回后 `draft` 键仍存在且值一致。
- 新 `tools.json` 被旧版本程序读到时（用户降级）：旧版本只读它认识的三个键，不崩溃、不删其它键
  （`JsonStore` 的读-改-写必须先读全量对象再改，不能重建整个对象）。
- 模板目录里放一个坏文件 → 只跳过它，其它模板可用，并记一条警告。
- 崩溃恢复副本在正常退出后被删除；异常退出后下次启动能读到。
- 会话：正常关窗 → 重开恢复；JSON 损坏 → 整体作废 + 警告，不崩溃。
- 书签（若实施）：存储写入路径与 .md 本体路径集合无交集（用例 30）。
