## 一、布局：统一窗口，双预设

```
┌──────────────────────────────────────────────────────────────────────┐
│ RibbonBar（单行模式，可折叠；文档模式默认 minimumMode）                  │
│  标签页：开始(Markdown) · 提示词 · 上下文 · 草稿 · 视图                  │
│  （文档模式下「提示词/上下文/草稿」三个 tab 不出现——挂成上下文页）        │
├───────────────┬──────────────────────────────────┬───────────────────┤
│ 左：属性操作区 │ 中：文档区                        │ 右：属性操作区     │
│ · 工作区       │  文档 tab 条（草稿 + 文件混排）     │ · 体检结果         │
│ · 文件树       │  查找/替换条（Ctrl+F 时滑出）      │ · 上下文预算明细   │
│ · 模板库       │  Preview / Split / Source 三态    │ · 草稿历史/快照    │
│ · 收藏夹       │  ATextArea + Markdown高亮         │                   │
│               │  状态条：字符 · 行 · 估算 token    │                   │
└───────────────┴──────────────────────────────────┴───────────────────┘
```

与第 2 版草案的四点关键差别：

1. **窗口是独立的 `ApplicationWindow`**（由预览窗演化，归 workbench 域），不是主窗里的页面。
   外壳侧栏不再有「Agent Tools」页，取而代之的是**启动页**（主按钮 + 最近草稿 + 最近文档 +
   新建草稿，条目名「Markdown」）；窗口跨页常驻——切到 agent 网页 tab 粘贴再切回，
   编辑器状态不丢（这解决了切页销毁丢撤销栈/滚动/选区的问题）。
2. **中间区从「草稿区」升级为「文档区」**：tab 条混合草稿与文件（统一 tab 模型，见
   `提示词撰写-12` §三），三态（Preview/Split/Source）从预览窗带进来、对草稿同样生效
   （渲染管线吃文本不吃文件）。编辑器本体统一为 `ATextArea` + `MarkdownHighlighter` +
   `MarkdownEdit`。
3. **页面头部（`PageHeader`）消失**——窗口没有「页头」这个概念，页面身份由
   `RibbonBar.applicationLabel`（左上角文字按钮，即文档名/窗口标题）承担。
   窗口 `title` 沿用预览窗惯例：文档名在前 + 应用名。
4. **「交付」标签页已删除**（D4/D5 移出规划）：Copy 家族并入「开始」页剪贴板 Panel +
   快速访问栏；体检与输出预设并入「提示词」页。标签页从 6 个变 5 个。

### 1.1 侧面区的形态

- 左右都是**可折叠的纵向堆叠面板**（各自 2–3 段），段头可点开合，折叠状态持久化。
- 左区三段：**工作区与文件树**（默认展开）、**模板库**、**收藏夹**；三者用同一套
  `ASectionHeader` + 列表的形态，不要引入 Tab 与堆叠两套机制。
- 右区两段：**体检结果**（默认展开）、**上下文预算 / 草稿历史**。
- 折叠后留下一条窄边（可点击展开）；不做「拖宽/拖窄 + 折叠」两套交互叠加。
- **文档模式预设**：侧栏收起为窄边、Ribbon `minimumMode` 折叠——它就是原来的
  Markdown 预览（大纲、搜索、三态、保存导出都在「开始/视图」两个 tab + 窗口周边），
  只是住在同一个壳里。侧栏/Ribbon 的开关不锁死，用户随时可展开。
- 两套预设的界面状态**分别持久化**（`提示词撰写-12` §2.2）。
- 中间文档区继续用现有的 `Flickable + TextArea.flickable` 结构（滚动、光标随动、
  外框固定视口），**不要**因为加了 Ribbon 就换掉它。

### 1.2 侧栏导航条目与启动页

- `NavigationModel` 注册新的 `main` 区条目「Markdown」（图标 + 标题），点击 =
  打开/聚焦工作台窗口（跨页常驻）。`PageDescriptor` 仍要注册（导航模型以页面为节点），
  但该页内容就是启动页（薄壳），不是编辑器本体。
- 启动页形态：`PageHeader`（标题「Markdown」+ 副标题）+ 主按钮（打开工作台 /
  新建草稿）+ 两组列表（最近草稿、最近文档，各取前 6，点击 = 开窗并开对应 tab）+
  空态引导。复用 `AButton` / `AListRow` / `AEmptyState` 货架件，不新造视觉。
- 最近文档列表的维护（MRU）归 E 组会话/打开记录，不与 `tools.json` 的 `workspaces`
  混用（一个是「看过的文件」，一个是「草稿绑定的目录」，语义不同）。

## 二、Ribbon 的页面设计

### 2.1 形态选择

**用单行模式**：`ribbonStyle: Ribbon.RibbonStyleCompactSingleRow`（tab 在标题行上）
或 `Ribbon.RibbonStyleLooseSingleRow`（tab 在标题行下）。

取舍：

- 单行模式把 ribbon 压到约一行按钮 + 一行 tab 的高度，对「中间文档区要尽量大」这个窗口的核心诉求最友好；
- 代价是 `proportion` 失效（`Large`/`Medium`/`Small` 一律按小按钮渲染），**按钮的主次不能靠大小表达**，
  只能靠标签页归类 + Panel 顺序 + `RibbonSeparator` 分组；
- 单行模式下 `wordWrap` 关闭，**按钮文字要短**（英文源串建议 ≤ 12 字符，中译也短）；
- 面板标题默认隐藏；若要显示需在 `RibbonPanel` 上显式打开并**实测**它是否被 `ribbonStyle` 传播覆盖
  （见 `提示词撰写-11` §三）。
- 建议同时用 `minimumMode` 做「折叠 Ribbon」开关（绑到「视图」标签页的一个 checkable 按钮，
  状态持久化）——单行 + 折叠后垂直占用可以降到只有一行 tab。
  **文档模式预设默认折叠**（看文档不需要整条功能带）；提示词模式预设默认展开。

### 2.3 QML 侧实现骨架（示意，不是最终代码）

```qml
// 窗口根在 src/workbench/qml/MarkdownWorkbenchWindow.qml；ribbon 是常驻项，不放进 Loader
RibbonBar {
    id: workbenchRibbon
    ribbonStyle: Ribbon.RibbonStyleCompactSingleRow
    applicationLabel: currentTabTitle()

    RibbonQuickAccessBar {   // 标题行右侧的高频小按钮
        RibbonToolButton { text: qsTr("Copy");  iconSource: "qrc:/icons/copy.svg";
                           proportion: Ribbon.Small; onClicked: window.copyActiveDocument() }
        RibbonToolButton { text: qsTr("Save as Template");
                           onClicked: window.saveAsTemplate() }
        RibbonToolButton { text: qsTr("Check"); checkable: true;
                           onClicked: window.toggleChecks(checked) }
    }

    RibbonCategory {
        title: qsTr("Start")
        RibbonPanel {
            panelTitle: qsTr("Font")
            RibbonToolButton {
                text: qsTr("Bold"); iconSource: "qrc:/icons/bold.svg"
                proportion: Ribbon.Small; checkable: true
                checked: MarkdownEdit.boldActive(editor)   // 需新增的查询接口
                onClicked: MarkdownEdit.applyBold(editor)
            }
            // ...
        }
    }
    RibbonContextCategory {
        // 提示词工作区专属的三个 tab：文档模式（无草稿 tab 激活）不激活
        contextTitle: qsTr("Prompt")
        active: hasDraftTabActive
        RibbonCategory { title: qsTr("Prompt") /* 模板/收藏/检查/预设 */ }
        RibbonCategory { title: qsTr("Context") }
        RibbonCategory { title: qsTr("Drafts") }
    }
    // 「视图」页所有 tab 共用
}
```

要点：

- 动作全部转发到现有的 `MarkdownEdit` 静态光标操作与门面方法；**ribbon 只做入口，不含逻辑**。
- `checkable` 按钮要反映光标处状态 → 需要 `MarkdownEdit` 新增「查询当前光标处是否已加粗/是否是标题第 N 级」
  之类的 `Q_INVOKABLE` 查询（现有类只有三个动作，没有查询侧）。
  没有查询接口的按钮**不要设 `checkable`**，否则就是一个会骗人的按钮。
- 弹出式交互（变量表单、模板管理、区间输入、快捷键表、体检明细）**统一用 `Loader` 惰性创建**，
  绝不在 ribbon 内急切实例化 `Popup`/`Dialog`（见 `提示词撰写-11` §四.2）。
- 文档模式的 tab 隐藏用 `RibbonContextCategory`（`active: false`）而不是逐个
  `hideCategory`——上下文页是 SARibbon 为「这类页面专属工具」准备的机制，
  正好语义吻合；实现期实测它按 `contextTitle` 的渲染形态（见 `提示词撰写-11` §六）。

## 三、主题对接（两套设计系统的唯一接触面）

- ribbon 用 `RibbonTheme`，本应用用 `theme.*`。**唯一允许的接触面是一个桥接组件**
  （例如 `RibbonThemeBridge.qml`，`Connections { target: theme; function onChanged() { ... } }`），
  它把 `theme.accent` / `theme.surfaceBg` / `theme.textPrimary` / `theme.borderSubtle` 推到
  `RibbonTheme.setAccentColor / setContentBgColor / setTextColor` 与 `currentTheme`（深色走 dark 系）。
- 桥接方向**单向**（应用主题 → ribbon），不要双向同步，也不要两边各留一套「跟随系统深色」逻辑
  （ribbon 自己有 `followSystemDarkMode`）。
- `RibbonTheme` 的 `setAccentColor` 会覆盖调色板的 accent 并重算依赖令牌，所以**每次主题变化推一次即可**，
  不要每帧推。
- 窗口自己的 QML **一律不写 ribbon 令牌以外的颜色字面量**；`check_architecture` 的
  「QML 无字面颜色」规则仍然约束**本仓**源码。
- 需实测：`RibbonTheme.dark` 与本应用 `theme.variant` 的对应关系，以及 deep-dark 调色板下
  ribbon 的按钮文字/图标对比度。

## 四、必须遵守的架构边界

### 4.1 依赖方向与窗口归属

- **统一窗口 QML 归 `awb_workbench`（L3）**：`src/workbench/qml/MarkdownWorkbenchWindow.qml`
  （workbench 域新增 qml/ 目录与资源登记）。它横跨 tools（草稿）与 markdown（预览会话），
  只有 L3 可以同时认识两者。`app/main.cpp` 的装载/注册照旧，`MainWindow.qml` 的
  Loader `source` 换成新 URL。
- `awb_tools` 与 `awb_markdown`（C++ 库）照旧**互不依赖**、各自只依赖 `awb_core` +
  `awb_theme`（markdown 另有 `awb_markdown_webengine` 适配器）；
  **都绝不链接 SARibbon**。Ribbon 的集成点在 `app/`（CMake 链接 + `main.cpp` 注册）与
  QML 的 `import SARibbon`。
- 直接后果：
  - 模板头部解析自带最小实现，不能复用 skill 域的解析器；
  - 跨域动作（「从文档新建草稿」「插入引用到草稿」「打开预览」）走 `workbench` 的新意图方法；
  - `src/workbench/qml/` 下的 QML 可以 import SARibbon 与两个域的门面（L3 合法），
    但 `src/tools/`、`src/markdown/` 的 C++ 里**不 include SARibbon 头**，也不互相 include。
- `src/tools/`、`src/markdown/` 内不许出现跨域 include；`Qt::Quick` 仍是 PRIVATE 链接。
- shell 的例外条款改写：`MainWindow.qml` 的 Loader 装载 workbench 域的
  `MarkdownWorkbenchWindow.qml`（按资源 URL），不再直接装载 markdown 域的窗口——
  `docs/architecture/分层与依赖.md` 的「唯一例外」表述随之更新（文档同步见 `提示词撰写-10`）。

### 4.2 QML → C++ 可调用性（既有红线）

- QML 要调的每个方法必须 `Q_INVOKABLE`（或槽/信号），要赋值的每个属性必须有 `WRITE`。
- 新增带命名空间的 QObject 类若含用户可见字符串，要按仓库既有先例用显式上下文翻译
  （否则 `tr()` 的运行时上下文与 lupdate 记录不一致，静默不翻译）。
- 返回自定义类型时写全限定名，否则 Qt 5 下 QML 会「按钮点了没反应」。

### 4.3 `objectName` 是测试契约

`promptEditor`、`editorMenu`、`fileTree`、`treeRowMenu` 已被 `tests/tools/tst_toolsui.cpp` 使用
（窗口迁移后这些名字跟着窗口走，测试装载目标同步改）。新增面板与关键控件都要给稳定
`objectName`。**Ribbon 内部的控件由第三方 C++ 宿主创建，`objectName` 不一定可控**——
因此交互冒烟要以「驱动门面方法 + 断言状态」为主，对 ribbon 按钮的点击测试改为在窗口上暴露
可测的 `Q_INVOKABLE` 入口，或直接在 C++ 层测 `MarkdownEdit` 的纯函数（这也是仓库既有的做法）。

## 五、QML 契约的既有坑（新增 delegate / 列表时逐条核对）

1. **delegate 的 `required property` 按「属性名 = role 名」匹配**，且根类型带同名视觉属性会**遮蔽**。
   根用 `Item` + required property，视觉背景放内层子项。
2. **声明了任何 required property 后，Qt 5.15 会清空 `contextObject`**，裸 `index` 抛
   `ReferenceError` 并中止整个 handler；`index` 也要显式声明。
3. **`ListView` 没有池化信号**，模型 reset 期间要手动闭掉动画（现文件树的 `rebinding` 做法）。
4. **字面颜色一律禁止**（`#rrggbb`、`Qt.rgba(数字, …)`）；只用 `theme.*` 语义令牌。
5. **`AEmptyState` 的根是普通 `Item`、不能带 `anchors`**；内部用 `Column` 而不是 `ColumnLayout`。
6. **窗口是独立 `ApplicationWindow`，不是页面**：`previewWindow` 一族经验直接适用——
   字体挂窗口级（`font.family` 需 `ApplicationWindow`）；关窗走 `onClosing` 报告位
   （`notifyWindowClosed()` 幂等）+ `Component.onDestruction` 兜底，否则 Loader 永远持有隐藏窗口。

## 六、i18n 与资源

- 本仓所有面向用户字符串：英文源串 + `qsTr()` / `tr()`（`check_architecture` 拒绝非 ASCII 源串）。
- 新增可翻译文件登记两处：`app/CMakeLists.txt` 的资源清单（含别名）与 `cmake/AwbTranslations.cmake`。
- **ribbon 自带的字符串（`RibbonCustomizeDialog` 等）不在本仓 `.ts` 范围内**，中文环境下会是英文；
  对策见 `提示词撰写-09` 决策记录 D-9。
- 新增图标：`icons/` 加 SVG + `app/CMakeLists.txt` 资源清单登记。ribbon 会以 20×20 栅格化，
  现有 24×24 画布的图标要实测清晰度（`提示词撰写-11` §六.4）。
- 新增数据文件（内置模板、体检词表）同样进资源清单，遵守「内置 + 用户覆盖」惯例。
- **SVG 依赖是新增的**：`SARibbonQml` 的 CMake 里 `find_package(... Svg)`，
  发布包（`scripts/package.sh` + windeployqt）要确认带上 `Qt6Svg.dll` 与 SVG 图像格式插件。
- **窗口 QML 移库**：`MarkdownPreviewWindow.qml` → `src/workbench/qml/MarkdownWorkbenchWindow.qml`
  意味着 `app/CMakeLists.txt` 资源别名从 `markdown/` 变 `workbench/`、
  `AWB_TS_SOURCES` 条目同步改路径；`tests/markdown/` 两个 UI 测试的装载 URL 同步改。

## 七、Qt 5 / Qt 6 双版本

- 任何新代码两条路线都要能编译；版本判定走 `QT_VERSION_MAJOR` / `#if QT_VERSION`，
  构建期差异集中在 `cmake/AwbQtCompat.cmake`。
- SARibbon 自身是 5.12+ 双版本（其示例里有 `QT_VERSION < 6` 的样式名分支），
  但**本文所述的一切组合都要在 Qt 5.15.16 与 Qt 6 上各验证一次**。
- 本规划的控件（`ListView`、`TextArea.flickable`、`RibbonGallery`）两版本都可用；
  仍要小心 QML 独有类型与枚举全限定名写法（ribbon 的枚举必须写成 `Ribbon.XXX`）。
- **Qt 5 / 无 WebEngine 构建里的窗口形态**见 `提示词撰写-12` §九：提示词模式全可用
  （预览 pane 隐藏），文档 tab 与双击 .md 不可用（报因）。窗口 QML 里对预览 pane 的
  条件渲染以能力位为条件，**不要在 QML 里写 `#if` 之类的编译期判断**——两版共用同一份 QML，
  运行期能力位裁剪。

## 八、测试与门禁

- 「做完」= `bash scripts/build.sh --test` 全绿（含 `check_architecture` 5 条规则）。
- 用例必须写在 `private Q_SLOTS:` 里（大写宏；小写 `slots` 后面的用例会编译通过但不执行）。
- 纯逻辑（模板解析、变量求值、体检规则、预算估算、文档操作、会话序列化）都要有脱离 QML 的用例；
  新增 `.cpp` 加进 `src/tools/CMakeLists.txt`（或 workbench 域的清单），用到 `tr()` 的加进 `AwbTranslations.cmake`。
- **引入 SARibbon 的构建选项会引入一条新的构建矩阵轴**（开/关），
  建议 CI/本地至少各跑一次「开」与「关」，确保关闭时没有残留的 `import SARibbon` 硬引用
  （做法参考仓库既有的 `AWB_ENABLE_WEBENGINE` 守卫：QML 侧用 `Loader` 以能力位为条件，
  或在 `app/CMakeLists.txt` 里按开关决定是否登记该 QML 文件）。
- **窗口迁移本身的冒烟**：workbench 域新增窗口 QML 后，`tst_markdownpreviewui` 的装载
  目标与用例平移；`tst_toolsui` 的页面级用例迁到窗口级（objectName 约定不变）。
- 测试不许依赖网络、本机已安装 agent 或真实数据目录。

## 九、开发流程约束（本仓库常态）

- 不在主工作树的 `dev` 上直接开发：`bash scripts/worktree-add.sh feat/tools-<topic>`；
  完成后合并回 `dev` 并删除工作树/分支。
- 引入第三方库（submodule 注册）这种「大而横」的改动**单独一个工作树 + 单独一个提交**，
  与功能改动分开，保证任一方可独立回滚。
- 只提交本次任务相关文件，不要 `git add -A`。
