## 一、已拍板的决策记录

### D-1 · 「发送到 agent」——**整体移出规划**（原决策 1）

不做发送，也不做「默认关闭但可开启」。本窗口**不存在任何发送路径**：回车只换行，
交付只有复制。原第 2 版方案里 D5 的三档能力、二次确认、发送开关、token 红线整套复杂度
**全部删除**；「绝不误发」的产品主张原样保住（`docs/development/agent-tools.md` 的表述
在窗口整合后平移到新文档，措辞从「页面没有发送动作」改为「窗口没有发送动作」）。

- 影响：`提示词撰写-05` 的 D5 删除、D4（目标 agent 绑定）随之移出——没有发送后
  D4 只剩「推荐模板」这类弱价值，不值得维持一个 agent 选择器与两条 Ribbon 入口。
  「交付」标签页解散（见 D-2）。
- 若不定会怎样：已定，无此项。

### D-2 · Ribbon 标签页地图——**5 tab 溶解方案**（原决策 5/7/10 的合并重排）

D4/D5 移出后原「交付」tab 只剩 Copy 家族与体检入口，单独立 tab 太薄。定案：

- Copy 家族 → 「开始」页剪贴板 Panel + 快速访问栏（Copy 是主交付动作，最高频，放最顺手处）；
- 体检（Check Prompt / Checklist / Fix All Safe Issues）与输出预设 → 「提示词」页；
- 标签页定稿 5 个：**开始 / 提示词 / 上下文 / 草稿 / 视图**；
- 文档模式（双击 .md）下「提示词/上下文/草稿」三个 tab 挂成 `RibbonContextCategory`
  且不激活，只剩「开始/视图」——文档模式约等于原预览窗 + 可展开的完整工具。

### D-3 · 草稿与文件统一为**同一套文档 tab 模型**（原决策 2 的扩展）

一条 tab 条，每 tab 一份文档，backing 两种：`file`（磁盘 .md，预览域管线）与
`draft`（`tools.json` 草稿，id 引用）。**分两步落**（见 `提示词撰写-12` §3.2）：

1. M1：预览控制器多会话化 + 文件 tab（草稿仍是唯一隐式草稿 tab）；
2. M4：多草稿（D1）落地时草稿并入同一条 tab 条。

草稿与工作区的关联语义不变（每条草稿带 `workspace` 字段，切草稿切文件树——
文件树是左侧栏的一段，跟 tab 条独立）。代价（已在决策时知情接受）：
`MarkdownPreviewController` 从单文档单例改造成多会话容器是**全方案最重的单点工程**，
`提示词撰写-12` §八已把它标为最大风险项。

### D-4 · 统一窗口承载形态——**独立窗口 + 侧栏启动页**（新增）

提示词撰写整体搬进从预览窗演化的「Markdown 工作台」独立窗口；外壳侧栏不保留编辑器页面，
改为**启动页**（条目名「Markdown」）：打开/聚焦工作台主按钮 + 最近草稿 + 最近文档 +
新建草稿。窗口跨页常驻（不随页面切换销毁）——「写 → 切 agent tab 粘贴 → 切回」的
核心工作流不再丢撤销栈/滚动/选区。启动页归 shell 页面体系（薄壳，无编辑器本体）。

### D-5 · SARibbon 引入方式——**git submodule**（原决策 6）

`third_party/SARibbon`，远端 https://gitee.com/czyt1988/SARibbon （用户已写明）。
构建期 `add_subdirectory` + `SARIBBON_BUILD_QML=ON`、
`SARIBBON_BUILD_WIDGETS/EXAMPLES/TESTS/INSTALL=OFF`；`AWB_ENABLE_RIBBON` 开关保留
（默认 ON；submodule 恒在工作树里，但构建开关让「不想编 ribbon」的构建可以裁掉）。

- **离线初始化沿用 spdlog 惯例**：SARibbon 与 spdlog 同在 czyt1988 的 gitee——
  本机内网对 gitee 不可达，`worktree-add.sh` 已实现的「submodule URL 临时指向主仓库
  已有检出、本地克隆」流程对 SARibbon 同样适用。前提：主仓库的
  `third_party/SARibbon` 需先在有网环境初始化一次（本地 `C:/src/Qt/SARibbon`
  检出可作克隆源）；base 移动带新 SHA 时先在主工作树 `git submodule update`。
- 新工作树初始化、`.gitmodules` 登记、CI 前置步骤都照 spdlog 的既有文档口径写。

### D-6 · 文件关联——**三件套，不做快速查看器**（新增）

argv 解析 + 单实例消息升级（`raise` → 可携带 `open:<路径数组>`）+ 设置页注册
（HKCU ProgId + OpenWithProgids，默认应用由用户在系统设置里选——UserChoice 有签名
保护，静默抢默认不可靠也不礼貌）。**不做**「不启动完整外壳的快速查看器」进程模式：
双击 .md 走完整启动，`guide/` 文案如实说明，不暗示是轻量查看器。
无能力构建（Qt 5 / WebEngine 关）隐藏注册入口、打开请求报因（见 `提示词撰写-12` §5.2）。

### D-7 · 草稿与工作区的关联——**一条工作区可挂多条草稿**（原决策 2）

每条草稿带 `workspace` 字段；切草稿即切文件树（树是左侧栏内容，不随 tab 销毁）。
切工作区不静默改动当前草稿，给「归到这个工作区 / 新建一条挂这里」的选择。
旧单一 `draft` 键读侧容错为「一条默认草稿」，不写迁移代码（不变）。

### D-8 · 模板存储——**一个模板一个 Markdown 文件**（原决策 3）

`<dataRoot>/prompt_templates/` 下每模板一个 `.md`（最小头部字段），用户能手改、能备份、
能分享；`awb_tools` 自带最小头部解析器（不依赖 skill 域）。内置模板
`config/default_prompt_templates.json` 随包只读，与 `default_agents.json` 同惯例。
收藏夹并入 `tools.json`（体量小、与草稿同生命周期）。

### D-9 · Ribbon 自带界面——**第一版不使用 `RibbonCustomizeDialog`**（原决策 9）

本窗口全部界面由本仓 QML 组装，不启用 ribbon 自带的自定义对话框——它的 `qsTr()` 上下文
不进本仓 `.ts`，中文环境下是英文。自定义（拖拽重排）第一版不做。
Ribbon 的主题跟随走单向桥接（应用 `theme` → `RibbonTheme`，原决策 8 的 A 案），
不引入 RibbonTheme 自己的调色板选择界面。

### D-10 · 会话恢复与启动行为——**默认手动开窗 + 打开时恢复**（新增）

应用启动不自动打开工作台窗口（不为 WebEngine 交启动税）；用户点侧栏/启动页/双击 .md
才开窗；**打开时**恢复上次 tab 组（文件按路径、草稿按 id）、激活位、三态、界面预设。
设置里留「启动时自动打开工作台」开关（默认关）。会话存数据根下独立 JSON
（见 `提示词撰写-07`），tab 数受上限约束。

### D-11 · 书签/高亮锚定——**标题/块级锚 + 本地存储**（新增）

书签与本地高亮锚在**标题/块级**（复用 `MarkdownChunker` 的块结构，与渲染
`<section>` 一一对应），存数据根本地 JSON，**绝不写回 .md 文件本体**；文件移动后
失配的书签标灰不删。高亮 = 选区映射为块级锚 + 颜色标记。行号锚（编辑即漂）与
精确文本 range（维护复杂）已否决。

### D-12 · 分节引用的目标草稿——**激活草稿 + 自动新建**（新增）

预览里选中一段生成 `` `./路径:起-止` `` 时：插入**当前激活的草稿 tab**；
没有草稿 tab、或激活的是文件 tab 时，**自动新建一条草稿**并插入，toast 告知去向
（「已新建草稿并插入引用」）。相对路径相对该草稿绑定的工作区计算。

### D-13 · 查阅功能优先级——**分节引用/会话恢复 P1，统计/书签 P2**（新增）

四项查阅功能全做，排序：E5 分节引用入草稿、E3 会话恢复（并入 M1 文档 tab 里程碑）为 P1；
E6 文档版统计（可搭 M2 预算条的车提前）、E7 书签/本地高亮（独立小里程碑，M6 前后）为 P2。

### D-14 · 模型辅助——**不进任何版本，单列为 P2 实验项**（原决策 4）

第一版只做纯规则体检；模型辅助若将来做，须单独决策且显式声明联网边界。
未拍板前不排期（不变）。

### D-15 · 里程碑顺序——**窗口骨架先行**（原决策 5 的重排）

M0 = SARibbon submodule 接入 + 提示词页与预览窗合并为统一工作台窗口（Ribbon +
双模式，动作迁移、功能维持现状）——一次改写到位，避免「先在旧页面做功能、
之后整个重写装配层」。完整里程碑表见 `提示词撰写-10`。
