## 三、分支与提交

- 用 `bash scripts/worktree-add.sh feat/tools-<topic>` 开工作树（例如
  `feat/workbench-window`、`feat/markdown-sessions`、`feat/tools-prompt-templates`、
  `feat/tools-multi-draft`、`feat/tools-prompt-checks`），**不在主工作树的 `dev` 上直接开发**。
- **submodule 注册单独一个工作树/提交**（`feat/add-saribbon`）：`.gitmodules` 一行 +
  submodule 指针 + CMake 接线 + `CHANGELOG.md`/许可说明，与窗口迁移彻底分开。
- 每个里程碑内部按功能切成原子提交：数据层（键位与读写）→ 纯逻辑（解析/规则/估算/会话）→
  QML 面板 → 冒烟测试 → 文档。
- 动手前先合并一次最新的 `dev`，收尾合并前再合并一次，让冲突提前暴露。
- 合并回 `dev` 之后删除工作分支与工作树；「任务完成」包含「已合并回 `dev`」。

## 四、风险与缓解

| 风险 | 缓解 |
|---|---|
| **多会话化重构出错静默丢命令/串文档**（全方案最重单点） | M1 主轴；先写会话生命周期时序图（打开/切换/关闭/外部修改/保存）评审再动刀；单会话行为先有回归测试再改造（`tst_markdown` 的队列用例是安全网） |
| SARibbon submodule 在内网不可达（gitee 同 spdlog） | `worktree-add.sh` 本地克隆流程已兼容；主仓库有网初始化一次后离线可用；`base` 移动带新 SHA 时先在主工作树 `git submodule update` |
| SARibbon 与既有构建/测试矩阵冲突（Qt 5、WebEngine 开关、静态链接） | M0 先按 `提示词撰写-11` §六 实测清单逐条验证；`AWB_ENABLE_RIBBON` 开/关各跑一次完整测试 |
| 第三方库把垂直空间吃光，文档区变小 | 默认单行模式 + `minimumMode` 折叠（文档模式预设默认折叠）；面板标题默认隐藏；按钮文字短 |
| 两套主题/两套菜单/两套设计系统并行，长期各自漂移 | 主题只留一个单向桥接点；菜单只让 `RibbonMenuItem` 进 ribbon、`AMenu` 留窗口内上下文；「动作只有一处出口」写成文档红线 |
| 窗口迁移与并行会话在 `ToolsPage.qml`/`MarkdownPreviewWindow.qml` 上冲突 | M0 期间冻结这两个文件（协调）；迁移后各标签页拆成独立 `.qml`（`RibbonStartTab.qml` 等），窗口文件只做装配 |
| Ribbon 里 `checkable` 按钮没有真实状态源 → 骗人的按钮 | 先补 `MarkdownEdit` 的查询接口与用例，再设 `checkable`（见 `提示词撰写-03` §2.3） |
| M4 的 `tools.json` 兼容出问题丢用户草稿 | 先写读侧容错用例（旧三键文件 → 完整保留），再动写路径；写盘始终走读-改-写的原子写 |
| 文件关联被误解为「轻量查看器」/静默抢默认 | 注册动作如实文案（默认应用去系统设置选）；`guide/` 明说冷启动走完整应用；不做快速查看器进程（D-6） |
| 查找条挤压编辑区高度 | 查找条只在 Ctrl+F 时滑出，不进 `Flickable` 滚动结构 |
| 体检规则误报惹人烦 | 每条规则可单独关闭；先只启用高置信的几条（路径方向、未填占位符、缺验收标准） |
| 会话文件记录的路径泄露工作目录结构（隐私） | 会话只存本地路径与草稿 id、不存正文；不加密不清理（「找回上次开着的」就是全部语义）；文档如实说明 |
| 侧栏启动页取代 Agent Tools 页改变老用户习惯 | 启动页保留「最近草稿」直达；侧栏条目名「Markdown」+ 图标仍在原位；`guide/` 给一句迁移说明 |
