# E 组 · 统一窗口与文件关联

> 索引见 `提示词撰写-00-总览与索引.md`；界面骨架与技术约束见 `提示词撰写-08`；
> 数据落盘见 `提示词撰写-07`；决策依据见 `提示词撰写-09` 的决策记录。
>
> 这一组是第 3 版新增的：**提示词撰写与 Markdown 预览合并为同一个「Markdown 工作台窗口」**，
> 并让这个窗口成为系统里打开 `.md` 文件的合理途径。它解决欠缺清单的
> **8（.md 没有轻量打开途径）**、**11（预览与撰写割裂）**、**12（长文档查阅手段薄）**。

## 一、功能表

|---|---|---|---|
| E1 | 统一工作台窗口（双模式） | **P0** | 提示词模式与文档模式是同一个窗口的两种预设 |

## 二、E1 统一工作台窗口（双模式）

### 2.1 载体与生命周期

- 窗口由现有 `MarkdownPreviewWindow.qml` 演化（改名 `MarkdownWorkbenchWindow.qml`），
  仍是 `ApplicationWindow`，仍由 `MainWindow.qml` 的 `Loader` 按需创建、**关掉即销毁**。
- **装载条件不再含 `markdown.available`**：提示词模式（纯 QML 编辑器 + 高亮）在
  无 WebEngine 的构建里照常可用；预览 pane 与文档模式才受能力位约束（见 §九）。
- 保留「关掉即销毁」而不是常驻：WebEngineView 是 Chromium 渲染进程 + 约 4 MB 运行时，
  常驻等于每次启动都交税。代价是重开窗口要重建渲染面——会话恢复（E3）保证内容不失，
  这是「内容状态放 C++ / 视图可毁」既有原则的延续。

### 2.2 两种模式是「预设」，不是两个应用

模式 = 一组界面配置的预设，不是两套代码路径：

| 配置项 | 提示词模式 | 文档模式 |
|---|---|---|
| 左右侧栏 | 全开（工作区/文件树/模板/收藏 + 体检/预算/历史） | 收起（一条可点击展开的窄边） |
| Ribbon 标签页 | 全部 5 个（见 `提示词撰写-08` §2.2） | 「开始 / 视图」——「提示词/上下文/草稿」三个 tab 挂成 `RibbonContextCategory`，文档模式不激活 |
| Ribbon 折叠 | 展开为默认（`minimumMode` 可切） | **`minimumMode` 折叠为默认**（看文档不需要整条功能带），点击 tab 行即展开 |
| 中间区 | 文档 tab 条（草稿 + 文件混排）+ 三态 + 状态条 | 同一套中间区（tab 条上通常只有一个文件 tab） |

- 用户可以在文档模式里手动展开侧栏、展开 Ribbon——「视图」标签页本来就有面板开关；
  预设只决定**默认长什么样**，不锁死。
- 两套预设的界面状态**分别持久化**（折叠了哪个侧栏段、Ribbon 折叠位、三态），互不污染。
- 模式切换入口：视图 tab 的「完整工具」开关（即侧栏预设切换）；以及 §四的
  单向升级口。**没有「模式」这个用户概念**——用户视角里只有一个窗口，
  工具多一点少一点而已；「提示词模式/文档模式」是本文档内部的术语。

### 2.3 统一编辑器

- 预览窗源码区（裸 `ATextArea`）升级为与提示词区同一套：
  `ATextArea` + `MarkdownHighlighter` + `MarkdownEdit` 静态动作。
  B 组的格式动作（`提示词撰写-03`）对**草稿 tab 与文件 tab 的源码编辑同样生效**。
- 文件 tab 的保存沿用预览域的**字节保真**语义（BOM/换行/UTF-8 形状记录在
  `MarkdownDocument`，保存不重写文件）——这套能力原样带进统一窗口，不重做。
- 草稿 tab 照旧写 `tools.json`（500 ms 防抖 + 析构补写），与文件保存走不同通道、互不干扰。

### 2.4 草稿也享受预览渲染

渲染管线（`MarkdownChunker` 分块 + 增量更新 + `content-visibility`）吃的是**文本**不是文件路径。
草稿 tab 的预览把草稿正文喂给同一管线即可：三态（Preview/Split/Source）对草稿同样可用。
这把 `提示词撰写-08` 第 2 版「中间草稿区只有编辑器」的方案升级成「编辑 + 预览同屏」，
长提示词的结构（标题、列表、围栏、mermaid 图）都能当场看见。

## 三、统一文档 tab 模型

### 3.1 模型

- 中间区顶部一条 tab 条，**每个 tab 一份文档**，backing 两种：
  - `file`：磁盘上的 `.md` / `.markdown` 文件（预览域既有能力）；
  - `draft`：`tools.json` 里的草稿（id 引用，正文仍在 tools 域）。
- tab 视觉区分：草稿 tab 与文件 tab 用小徽标（`APill` 形态）区分来源，避免「这条是文件那条是草稿」
  靠记忆。文件 tab 显示文件名，草稿 tab 显示草稿标题；脏标记（未保存）沿用编辑区现有语义。
- 关 tab ≠ 删文档：关掉文件 tab 只是关闭视图（文件还在磁盘）；关掉草稿 tab 只是移出 tab 条
  （草稿仍在 `drafts`，可从「草稿历史」段找回）——与 D1 的「关标签不删草稿」同一语义。
- 上限建议：文件 tab 8 个、草稿 tab 20 个（与 D1 草稿上限同量级）；超限提示
  「最久未查看的 tab 可关闭」而不是静默淘汰。

### 3.2 分两步落地（决策 D-4）

1. **M1：文件 tab**——把预览控制器从「单文档单例」改造成「多会话容器」，tab 条只装文件
   （此时草稿仍是窗口里唯一的一条「隐式草稿 tab」，行为同现状）。
2. **M4：草稿并入**——多草稿（D1）落地时，草稿 tab 与文件 tab 合入同一条 tab 条。

### 3.3 单渲染面的取舍

- 全窗口**仍只有一个 `WebEngineView`**：切 tab 换文档（按会话重新装载/增量更新），
  不为每个 tab 建一个渲染进程。这与预览窗「开第二个文件复用窗口换内容」的既有决策同源。
- 代价：切回一个之前看过的 tab 时可能有可感知的重装载。缓解方向（实现期实测再定）：
  页面侧按 docId 缓存已解析的块，或 C++ 侧保留会话的分块结果只重推 DOM。
  **不承诺切 tab 零成本**，但要保证「首屏只付第一个块的钱」这条管线既有优势不回退。

## 四、E4 从文档新建草稿（P1，单向升级口）

- 入口：文档模式的「视图」或「开始」页一条 **New Draft from This Document**。
- 行为：把当前文件**全文复制**为一条新草稿（原文件不动）；草稿标题取文件名（去后缀），
  工作区绑定 = 文件所在目录（若该目录在 `workspaces` 列表内则绑定，否则留空并提示）；
  然后切到提示词模式预设 + 激活该草稿 tab。
- 单向：升级后草稿与源文件**没有关联**——改草稿不会写回文件，改文件也不会同步草稿。
  这是有意的：升级的语义是「拿这份文档当提示词的底稿」，不是「双向编辑同一份内容」。
- 反方向不存在（草稿 → 文件）。「把草稿存成磁盘文件」如果将来有需求，
  属于 A7 导出家族的扩展，另行立项。

## 五、E2 .md 文件关联与命令行打开

### 5.1 三件套（决策 D-6）

1. **argv 解析**：`main()` 启动时扫描命令行参数里真实存在的 `.md` / `.markdown` 路径
   （后缀判定与预览域 `canPreviewPath` 同一规则），作为「打开请求」排队；
   主窗加载后开工作台窗口并逐条开 tab。无匹配参数 = 正常启动（显示外壳 + 启动页）。
2. **单实例消息升级**：第二实例目前只发 `"raise"`；升级为消息可携带打开请求
   （例如 `open:<json 路径数组>`，无请求时仍为 `raise`）。首实例收到后：
   已开窗口则开 tab + `raise()` 工作台窗口；未开则创建窗口。多文件 = 多 tab。
3. **设置页注册动作**：「关联 .md / .markdown 文件」按钮，写 HKCU：
   `Software\Classes\<ProgId>\shell\open\command = "<exe 路径>" "%1"`，并在
   `.md` / `.markdown` 的 `OpenWithProgids` 里登记该 ProgId。
   **默认应用由用户在系统设置里选**——Win10+ 的 UserChoice 有签名保护，
   静默抢默认既不可靠也不礼貌；我们的目标是出现在「打开方式」列表里。
   按钮旁给一句如实文案说明这一点。

### 5.2 边界与降级

- **冷启动成本如实告知**：双击 .md 打开的是完整应用（外壳 + 引擎初始化），
  不是秒开的查看器。「快速查看器进程模式」已明确不做（决策 D-6）；
  `guide/` 文案不暗示它是轻量查看器。
- **无能力构建**（Qt 5 / WebEngine 关闭）：设置页的关联入口**隐藏**；
  若此前关联过（用户换用了精简构建），argv/消息打开请求 → 工作台窗口照开，
  文件内容进不了预览（预览 pane 不可用时源码态仍可编辑查看?——不：
  **文档 tab 本身依赖预览域的文档管线，统一按「能力不可用」报因**，
  toast 说明原因并建议用外部编辑器。诚实报因优于半功能）。
- ProgId 残留：卸载/移除应用不清理注册表项（残留无害，Windows 惯例如此），
  不为此写清理逻辑。
- 路径异常（文件在打开前被删）：tab 进入空态并提示，不崩溃。
- 关联动作本身写 HKCU 失败（权限/策略）→ toast 报因，不静默。

## 六、E3 会话恢复

### 6.1 行为（决策 D-10）

- **默认不自动开窗**：应用启动只显示外壳 + 启动页。点击侧栏条目/启动页主按钮/双击 .md
  才开工作台窗口——启动不为 WebEngine 交税。
- **打开时恢复**：窗口创建时读取会话文件，恢复上次的 tab 组（文件按路径重开、
  草稿按 id 重开）、激活 tab、三态、侧栏折叠、Ribbon 折叠位。
- 设置里留一个开关 **「启动时自动打开工作台」**（默认关）给重度用户——
  开了就是「上次开着就自动重开」，代价自负、文案如实。

### 6.2 会话内容与上限

- 存 `<dataRoot>/markdown_session.json`（名字实现时可调，见 `提示词撰写-07`）：
  tab 清单（`{kind: file|draft, path|draftId, 视图态}`）+ 激活索引 + 窗口预设与界面状态。
- 文件已不存在 → 该 tab 恢复为空态 tab（占位提示），不整窗失败。
  草稿 id 已不存在（被删）→ 跳过该 tab。
- 会话记录的 tab 数受 §3.1 上限约束；会话写盘在「tab 结构变化」时立即
  （增删/切换/预设变化），视图态跟随现有防抖节奏，不逐键写。
- 隐私口径：会话里只有本地路径与草稿 id，无正文、无敏感内容；不加密、不清理历史
  （用户要求「找回上次开着的」就是全部语义）。

## 七、E5 分节引用入草稿（P1）

- 交互：在**文件 tab 的预览区**选中一段（渲染区的文本选区，映射回源文档行区间）→
  上下文菜单或「上下文」标签页的 **Insert Reference into Draft** →
  生成 `` `./相对路径:起-止` `` 插入草稿。
- **目标草稿规则（决策 D-12）**：插入**当前激活的草稿 tab**；没有草稿 tab、或激活的是
  文件 tab 时，**自动新建一条草稿**并插入，toast 告知「已新建草稿并插入引用」。
  相对路径相对**该草稿绑定的的工作区**计算；草稿未绑定工作区时退回绝对路径引用
  （与 `fileReference()` 现有回退行为一致）。
- 行号口径：区间取**源文档真实行号**（分块器的 `startLine/endLine` 是行级状态机的产物，
  与渲染 `<section>` 一一对应——这正是预览域已有的锚）。
- 跨域路径：预览区（markdown 会话）到草稿（tools 域）是跨域动作，
  走 `workbench` 意图入口（见 §八），QML 不自己拼。

## 八、架构落点（本组特有）

- **窗口 QML 归 workbench（L3）**：`src/workbench/qml/MarkdownWorkbenchWindow.qml`
  （workbench 域新增 qml/ 目录）。理由：窗口横跨 tools（草稿）与 markdown（预览会话）
  两个域，只有 L3 可以同时认识两者；放 markdown 域会让领域 QML 反向引用兄弟域门面，
  放 app/ 则失去模块化资源登记的惯例。MainWindow 的 Loader 装载目标换成它
  （shell「按资源 URL 装载 markdown 预览窗口」的例外条款随之改写，文档同步见
  `提示词撰写-10`）。
- **多会话化是本组最重的单点工程**：`MarkdownPreviewController` 现按单文档设计
  （命令队列、docId、视图偏好、watcher、导出落点全挂在一个文档上）。改造方向：
  会话容器（`docId` 键控的会话对象，含 `MarkdownDocument` + 分块结果 + 视图态 + 命令路由），
  单 `WebEngineView` 复用换文档。**实施前先写一页会话生命周期的时序图再动刀**
  （打开/切换/关闭/外部修改/保存的交互比现在的单文档复杂一个量级）。
- 草稿 tab 的正文存取经 `tools` 门面（L3 合法直连）；「从文档新建草稿」「插入引用到草稿」
  这类**跨域意图**经 `workbench` 暴露 `Q_INVOKABLE`，供窗口与预览区调用——
  与现有 `previewMarkdown()` 的接法同一形态。
- 书签/高亮（E7）归 markdown 域（锚与渲染都靠分块器），存储见 `提示词撰写-07`。

## 九、Qt 5 / 无 WebEngine 构建里的形态

| 能力 | Qt 6 + WebEngine | Qt 5 / WebEngine 关 |
|---|---|---|
| 提示词模式（编辑/高亮/格式/模板/草稿） | 全部可用 | 全部可用（预览 pane 隐藏，三态退化为纯源码态） |
| 文档 tab / 双击 .md | 可用 | **不可用**（打开请求报因，见 §5.2） |
| 草稿的预览渲染 | 可用 | 不可用（退化为源码态） |
| 启动页、侧栏条目 | 可用 | 可用（文档列表点击时报因） |

统一原则沿用预览域既有口径：**功能缺失时不可见或不响应，而不是呈现一个坏掉的版本**。

## 十、验收要点（补入 `提示词撰写-06` 的用例清单）

- 模式预设：提示词模式开窗默认侧栏全开；文档模式默认收起 + Ribbon 折叠；
  两套界面状态互不污染（切换后各自记住）。
- 统一编辑器：文件 tab 的源码区有高亮、格式动作可用、保存字节保真（既有用例平移）。
- tab：文件/草稿混排、徽标区分、关闭语义（文件视图关/草稿找回）、上限提示。
- 会话：正常关窗 → 重开恢复 tab 组与激活位；文件丢失 → 空态 tab；草稿被删 → 跳过；
  「启动时自动打开」开关两态。
- 文件关联：argv 单文件/多文件；第二实例消息开 tab + 唤醒；注册动作成功/失败两路；
  无能力构建的报因路径。
- 从文档新建草稿：全文复制、标题与工作区绑定规则、单向无关联。
- 分节引用：目标草稿三态（激活草稿 / 激活文件 tab / 无草稿）；行号与选区映射正确；
  相对路径按草稿工作区计算。
- 书签/高亮（若实施）：锚定在编辑后不漂移；文件移动后失配标灰不删；存储不写回 .md 本体。
