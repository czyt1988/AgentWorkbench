# Markdown 预览

Markdown 预览是一个**独立窗口**，把一份 Markdown 文件显示成它本该被读到的样子：标题、表格、带高亮的代码、公式和图表。你也可以直接改文字，并存回同一个文件。

它不是侧栏里的一个页面。你从某个文件打开它，读文件或整理文件期间，它始终是自己那个窗口。

## 怎么打开一个文件

1. 进入 **提示词撰写**，选中文件所在的那个文件夹。
2. 在左侧的文件树里**对 `.md` 或 `.markdown` 文件点右键**。
3. 选择 **预览 Markdown**。

窗口打开时显示的就是渲染好的文档。窗口已经开着时再对另一个文件点右键，那个窗口会切到新文件，而不是叠出第二个。

**为什么没有 预览 Markdown 这一项？** 两种可能：这个文件按后缀不是 Markdown 文件；或者本构建根本不具备预览能力——预览需要内嵌了浏览器引擎的那版本。没有能力时这一项压根不出现，所以不存在「点了才发现不行」。

## 三种视图

工具行最左边那几个按钮切换你看到的东西：

- **预览** —— 只显示渲染结果。
- **分栏** —— 左边是 Markdown 源码，右边是渲染结果。
- **源码** —— 只有纯文本，什么都不渲染。

文件写不回去的时候，**分栏** 与 **源码** 是灰的；只有 **预览** 可用，底部状态栏会说明原因。

## 阅读

- **大纲。** 左侧面板列出文档的各级标题，点一条就跳过去。用工具行上的大纲按钮开关它（提示文字是 **显示大纲**）。没有标题的文档显示 **没有标题**。
- **文字大小。** 第一个下拉框选正文字号：**主题字号** 跟随当前的外观主题，也可以直接选 12 px 到 24 px 之间的固定值。
- **宽度。** 第二个下拉框选正文栏宽：**默认栏宽**、某个固定宽度，或 **满栏** 用掉整个窗口。
- **状态栏。** 显示文件路径、文件字节数、渲染组件的版本号；有没存盘的改动时显示 **有未保存的改动**；文件不能编辑时显示原因。

## 在文档里查找文字

按 `Ctrl+F`，或点搜索按钮。输入文字后用 **下一处** 和 **上一处** 逐个跳转，旁边的标签告诉你现在在第几处（**第 3 处，共 17 处**）。打开 **区分大小写**（Aa）就是大小写敏感搜索。`Esc` 收起搜索条。

有两件事它做不到，两件事都是因为「这个窗口靠什么把长文件渲染得快」：

- 它只统计**已经排版出来**的部分。非常长的文档刚打开就搜，命中数可能比过一会儿再搜要少——等整篇渲染完再搜一次就齐了。
- 它找不到被格式打断的文字。搜「调查」匹配不到 `强**调查**研` 里的这一段，因为加粗符号把这个词切成了几块。

## 编辑与保存

在 **分栏** 或 **源码** 里打字。窗口不会不打招呼就丢掉你的劳动：

- `Ctrl+S` 写盘。会有确认提示，**有未保存的改动** 也随之消失。
- 带着未保存的改动关窗，会问一句「关闭前是否保存对某文件的改动？」，三个选择：**保存并关闭**、**放弃更改**、**取消**。
- 你有未保存改动期间，别的程序改了这个文件，会弹出一个对话框：**从磁盘重新加载** 取外面那份、丢掉你这份；**保留我的改动** 留下你这份，并且不再为这一次外部改动反复追问。
- `F5` 从磁盘重读这个文件。如果你有未保存的改动，它会先问你，所以 `F5` 不会悄悄把你的编辑扔掉。

**保存会保留文件原本的样子。** 文件用的是 Windows 换行，或者开头带字节顺序记号，存盘之后还是如此。这个窗口不会把你的文件「整理」成另一种形态。

文件只读有三种原因，状态栏会说出是哪一种：太大、不适合在这里编辑（预览照常可用）；盘上不可写；或者文字不是合法的 UTF-8——这种存回去会造成永久损坏，所以直接拒绝编辑。特别大的文件（几十兆）根本不会打开，而不是打开之后卡在那里。

## 复制、在别处打开、导出

这些都在 **更多操作** 里（工具行右侧那个图标）：

- **复制所选内容** 复制你选中的那段渲染后的文字。先在预览区选中，否则应用会提示你未选中内容。
- **复制 Markdown 源码** 复制原始的 Markdown。
- **在浏览器打开** 把渲染结果写出一份副本，并用系统浏览器打开它。副本落在应用自己的数据目录里、按文档名命名，所以对同一个文件再用一次会覆盖那份副本。
- **在文档旁导出 HTML** 在 Markdown 文件旁边写出一份自包含的 HTML。
- **导出 HTML 到指定文件夹…** 由你挑目录。

两种导出完成后都会给一条说明文件位置的消息，并带你看到它落在哪儿。两者都会先把整篇渲染完再落盘——图表很多的文档会稍等片刻才出现文件。

关于导出有一点要注意：导出件引用图片用的是**相对文档的路径**，所以图片只有在 HTML 与它们放在一起时才显示得出来。导出到别的目录是你的选择，但图片不会跟着走。

## 哪些内容会渲染，哪些不会

公式、图表、表格、任务清单与代码高亮都可用。具体说：

- 用 `$$ … $$`、`\[ … \]` 以及行内写法写的公式会排成真正的数学式子。写错的公式显示成红色，而不是被藏起来。
- 语言标记是 `mermaid` 的代码块会变成图表。图表是滚到附近才画，不是一次全画——图表非常多的文档会让你点一下某张图再画它。
- GitHub 风格的提示块（`> [!NOTE]` 以及另外四个）画成带语义色的告警条。
- **文档里内嵌的 HTML 不渲染。** 直接写在 Markdown 里的标签会显示成正文文本。这是刻意的安全选择：这个窗口看的是不是你写的文件，而文档里的 HTML 本来能在应用里执行代码。

## 出问题了怎么办

**预览窗口什么都没有。** 先看状态栏，文件读不了时它会写明原因。空文件在预览区显示 **文档为空**，在编辑区显示 **没有可编辑的内容**。

**图表是空的或报错。** 解析不过的图表会显示 **图表无法绘制**；在 **源码** 里改好文字，这一块会自己更新。图表很多的文档里，占位上写着 **点击渲染此图表**，不点就一直空着——这是窗口拒绝把几十张你不会去看的图全画出来。

**有内容没渲染成功。** 文档中某一块失败时会给出提示，其余部分照常显示——窗口不会安静地留半页空白给你。

**窗口不肯打开第二个文件。** 这不是故障：一个窗口一次只看一份文件。打开另一份会替换当前的那份（会先问未保存的改动）。

**正文好好的，只有公式和图表区域一直是空的。** 这通常意味着页面没能取到它自己的资源。重新打开该文件；如果一直如此，说明本构建的预览组件没有正确安装，提示里会说明原因。
